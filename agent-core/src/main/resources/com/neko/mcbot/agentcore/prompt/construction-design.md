# 设计并建成一栋能住的房子

把主人给出的用途变成完整的建筑图，再把这张图做完。普通住宅默认包含实际门、床、工作台、
收纳、照明、窗、完整屋顶和室内通路；主人已要求的内容无需再确认。材料不足就准备材料。
“门洞留了位置”“家具以后再放”都不算这些功能已经完成。

先做下面五件事，再登记目标：

1. 核对场地和地板高度，选定朝向与实际入口。
2. 安排室内生活区、工作区和收纳，留出连接它们的通路，再决定外墙尺寸。
3. 画屋顶剖面，确定两侧坡面、山墙、屋脊与檐口怎样接合。
4. 把门和家具写成真实方块格；最后检查区域叠加有没有把它们覆盖成空气或墙。
5. 用 build_diff 检查整图材料及 design_components。住宅的 doors、beds、crafting_tables、
   containers、lights 为零时，先检查是不是漏写了功能，不要将一个没有门的外壳登记为完整住宅。
   stairs、slabs 是图纸所用构件的数量，不是屋顶美观或封闭的自动评分。

登记后直接在 run_program 执行 return mc.build()。mc.goal() 可取原 target/expected_revision，
mc.build_diff() 核对原图。不要在每次施工或历史整理后重画房子，修订哈希不是 instance_id。
图纸最多16384个唯一格，可用 regions 紧凑表达；不为旧128格限制把房子缩成方盒。
执行层不会替你发明图中没写的门、床和屋顶，也不会因脚本返回成功就认定整栋完成。

## 由活动空间确定大小

先布置床的两格和床边可站的位置，给工作台留操作面，给箱子留打开与走近的空间，
再从入口画出连续的通路。把家具沿墙组合，避免把工作台摆在中央或进门必经之处。
房间的净面积应在扣除家具后仍能活动；外墙厚度、门廊和屋檐在这之外增加。

没有尺寸要求时，独居小屋可以从净宽五至七格、净深六至九格比较起；这是起草的尺度，
不是固定模板。普通住宅或主人希望宽敞时，可从净宽七至十格、净深九至十二格起草；
多人或储藏较多时继续增加净尺寸或分区。不要只用“五乘五”
代表小屋：五格外宽扣掉两面墙只剩三格室内，放床和工作区后很容易挤成过道。
室内脚面以上至少保留三格舒适净高，门口和梁下单独检查，不能让屋顶压住家具和头部。

从远看轮廓决定主体与附属部分：一个较长的主体加入口门廊、侧边储藏间或退进去的窗区，
通常已有明确主次。扩大的房子应增加可用空间和体量关系，不是把同一个立方盒子放大。

## 地板、门与地形

地板是一层实际方块，身体站在它的顶面。以相对坐标说明：地板位于 y=0 时，普通整块
地板上站立的脚格是 y=1，门的 lower 也在 y=1，upper 在 y=2。墙从地板上开始。
不要在门下再加一层凸起的“门槛地板”，否则室内、门和外侧会差一个高度。

例如现场草地方块在世界 y=70：在它上面铺地板是 y=71，室内站立脚高就是72；
如果替换草地层作为地板，则地板仍在70，室内脚高71。先选其中一种，再统一全图。
门外地面低一格时，做真实可落脚的台阶或门廊，不要把“地面高度”直接填成墙底坐标。

入口要形成完整连接：外侧落脚点、台阶、门下半格、室内通路。两格高的通道没有被窗框、
梁、灯或家具堵住。玻璃窗的位置结合室内用途安排，窗台和窗上方保留墙体或框架。
坡地可用不同高度的基础支撑同一地板，或明确分层；四角都应落地，不能一侧埋进山坡、
另一侧悬空。草花、树叶及普通准备障碍按现场清理，不为常规清障另问主人。

实际门必须写完整两半，不能只指定两格空气。以下是入口部件的表达示例，位置由整栋方案决定：

```json
{"anchor":{"x":0,"y":0,"z":0},"cells":[
  {"x":0,"y":1,"z":0,"block":"oak_door","properties":[
    {"name":"half","value":"lower"},{"name":"facing","value":"north"},{"name":"hinge","value":"left"}]},
  {"x":0,"y":2,"z":0,"block":"oak_door","properties":[
    {"name":"half","value":"upper"},{"name":"facing","value":"north"},{"name":"hinge","value":"left"}]}
]}
```

这段只是门部件，不能单独替代整栋最终目标。放进 regions 图时，先表达墙和开口，
再写门两半；后写区域覆盖先写区域，最后一片空气不能擦掉已经写好的门或家具。
北为负 z、南为正 z、东为正 x。目标 rotation 会同时变换位置和已声明朝向，
不要先手工旋转朝向后再让目标旋转一次。

## 先把屋顶画通

先沿横跨屋脊的方向写出一条剖面，确认每排屋面连到下一排，再沿屋脊方向展开。
住宅屋顶要覆盖室内，封住两端山墙；只放两条檐边、留空中间，或把墙顶铺平，都不能
替代已经要求的坡顶。屋顶伸出墙面形成檐口，门廊可以有较低的附属顶，突出入口。

楼梯 facing 指向高的一侧，双坡屋面的两侧楼梯因此朝向屋脊。半砖 type=bottom/top
决定半格高度，type=double 是整格。相邻两排底半砖如果坐标直接升一整格，会断开；
在剖面里逐排检查接触关系，用可执行的楼梯或整块补足，而不是假定坐标像斜线就密封了。
屋面较宽时考虑较缓的剖面、分翼或错层，不要让一整块宽厅顶变成过高的尖塔。

把屋面、檐边、山墙和脊线当作不同部分处理。屋面负责连续坡度；檐边控制薄厚和投影；
山墙承接墙身；脊线清楚收住两坡。不是每一部分都必须换材料，但远看要有层次。
深色屋面配较亮墙身容易看清形体，石质基座、木质框架和少量玻璃也能自然分工。
主人明确要平顶时，可以做有檐边、女儿墙或高低变化的平顶，仍须完整覆盖室内。

## 材料与外观的取舍

先选结构语言，再挑现有材料。给主体、一处入口变化和屋顶一个清楚决定，然后在细节上呼应。

- 林间住处：框架清楚、窗区集中，入口有避雨过渡；让梁柱与室内木构接上。
- 田园住宅：较宽敞的生活空间、较低的门廊，工作和储物靠近侧门或附属间。
- 石木工坊：入口宽、基座明确，外墙可显示工作区的大窗和上层储藏。
- 山地住宅：顺坡的基础与入口台阶先成立，再考虑露台、较深的檐和较陡屋面。

这些是设计方向，不是必须照搬的房型或指定配方。按场地、材料和主人偏好组合。
窗、柱和梁有共同节奏，长墙需要入口、窗区或进退打断。用少量材料变化表达结构、
修补或旧化的位置，不要在每面墙随机撒上所有库存材料。
留一两处有意义的细节：门框更厚、窗下有窗台、门廊有柱、侧面有小退台。
选择这些细节时同时检查通行净空和实际放置支持，不能为外观堵住出口。

## 室内要能使用

每个生活层都应安排功能。睡眠区可由床、床边灯和小件收纳组成；工作区组合工作台、
收纳和操作空间；入口附近保留转身位置。较大的房间可以用地毯、半砖或梁分区，
不要把所有设施排成一条没有用途区别的长队，也不要让中央堆满方块。

床必须有 foot/head 两格，facing 从 foot 指向 head，两半朝向一致。head 就在 foot
沿 facing 方向相邻一格。与门相同，只从主格发一次原版动作，消费一件材料，两格都验收。
工作台、独立空箱、木桶、灯笼、火把、活板门、栅栏、墙和地毯可走当前放置链。
箱子只按独立空箱准备，不设计成自动合并邻箱，也不向图纸写容器内容。
其他设施或特殊装饰先查工具支持；无法可靠执行的状态在登记前换成可用构件。

吊灯的 hanging=true 需要上方支撑，落地灯的 hanging=false 需要下方支撑。
活板门用作窗边或架子时，要核对 half、open、facing 与实际原版放置结果，
不能假定执行器会把状态强行写出来。照明先覆盖入口、工作面和生活空间，
再安排视觉重点；悬在空中没有支撑的灯并不是可施工目标。

## 持续施工与收尾

登记一个完整目标，包含必要净空、门窗、室内设施和屋顶。用 cells、fill、regions
三种表达之一；regions 最多128区域，最后写入的同格生效。先看整栋料单再补缺口，
已有材料直接使用，缺床、门或照明材料不能成为从图中省掉它们的理由。

mc.build() 在本地连续查询、换位、清障与放置。默认连续工作，不主动设很小的 max_rounds
让每几格都回模型。它直接返回结果对象，字段不在 data 下；读取 status、goal_satisfied、
placed_blocks、cleared_blocks、remaining、blocked 和 design_components。程序返回成功
仅表示程序正常结束，status=blocked 或 goal_satisfied=false 就仍需处理真实缺口。

放置会封住当前站位最后出口时，would_seal_exit 表示先换外侧站位，再补这格；
不是删掉屋顶，也不是增加一份给主人签字的授权。导航允许已有安全落点的两/三格下降，
更高落差仍需真实台阶或可放置的临时支撑，所有工作保留实际材料、接触面与世界权限。
临时工位应在图纸和通路外，用 temporary_purpose=workstation 登记，不要把工作台放进
图中要求空气的室内脚格。临时支撑走原来源记录与回收接口，不能随意拆脚下成品或设施。

departure_blocked 表示当次搜索从起点没有任何可执行步骤，继续换远端目标不能解除出口障碍。
先依据回执中的坐标、身体与周围方块检查实际出口。一次局部目标失败仍可尝试其他候选，
但在身体、施工内容和材料都没有变化时，不要反复调用同一施工程序刷相同失败。
服务端确实返回 NEED_CONFIRM 时才按具体清单询问；NO_PATH、clear_allowed=false
和 no_clickable_face 本身不表示缺少主人授权。

大于32格的 mc.build_diff() 返回全局统计与有限明细，按 next_offset 及原 expected_revision
调用 mc.build_diff(target,revision,next_offset) 续查，用完丢弃旧页，不在 Lua 攒万格表。
某页没有工作与整栋未完成可以同时成立，整栋完成须由同修订全目标新鲜核验确认。
收尾检查实际门、通路、屋顶连接与室内功能；图纸漏项应如实说明，冻结后不暗改设计，
也不把遗漏说成“主人还没有决定是否需要”。
