# 建筑方案与现场施工

先理解主人要的是临时避难所、有人居住的小屋，还是有明确风格的作品。没有要求极简时，
不要把“屋内能站人”当作设计完成。模型决定形式和材料，执行层只按登记目标施工；
这份笔记没有固定房型、配方或额外的世界修改权限。

## 在登记目标之前

从现场选一个实际可用的入口，核对北为负 z、南为正 z，以及目标 rotation 对入口的影响。
把地板方块、站立脚格和门洞分别画清楚。先观察四角、入口和屋内地形；坡地可以局部填基础、
顺坡布置或做可落地的入口台阶，不必为追求同一个锚点反复整片挖平。

用一个完整方案表达基础、墙体、顶和必要的空格；草花和树叶挡住方案时，把需要的清空格
纳入目标并清理。不要只登记地板就把它当作整栋房子的最终条件。先查实际材料和支持状态，
确认整栋的差额后再获取材料，已有库存直接复用。

建筑的占地由用途和场地决定。先保证入口到屋内有连续通道，再安排室内活动区；
不能为了多一个装饰把通道堵死。对小屋，长方形主体搭配门廊或局部退台通常比每个面完全
相同更有层次。体量变化只需一两个清晰决定，避免无目的地把墙砌成锯齿。

## 把结构和外观一起考虑

为材料分配角色：底座负责落地感，立柱或墙角表明骨架，墙面保持安静，屋面形成轮廓。
这些角色可以共用材料，但至少要有明暗、颜色或形状上的区别。优先利用已能获得的材料，
例如把现有木板与少量原木、石料组合；无需为了装饰先展开一条漫长的稀有材料生产链。

长墙可以用窗、柱、门廊或进退关系分节。窗与屋内活动区对应，门上方留足净空。
不要把每种已收集的材料均匀撒到墙上；重复的结构节奏比随机斑点更像经过设计。
入口可以用独立的门框、稍低的门廊顶或外侧台阶强调，方向由主人要求和现场路线确定。

屋顶决定远看时的形状。先选屋脊方向，再画剖面，最后沿长度展开；
侧面墙、山墙和屋面需要接上，不能只有外围一圈檐口。单坡、双坡、折线或平顶都可以，
但平顶应有自己的檐边或高低关系，不能只是把最后一层墙填满。

楼梯和半砖能用少量材料做出坡度、檐口和薄厚变化。放置朝向、半格位置和相邻连接必须
使用当前工具实际支持的 properties，并经过原版预检；不要依赖直接改世界状态。
先用小段剖面核对上下两层是否连合，再展开整片屋面。屋檐适度伸出墙外，入口附近可以
与门廊衔接；屋顶不能让门上方变成低顶障碍。

细节应能解释用途：窗边有边框，入口有过渡，屋内保留工作或收纳位置，屋外有可走的落脚点。
选择当前支持并可放置的方块表达这些细节，不把不支持的灯具、床或其他组件写进目标后
再声称完成。暂时缺某种装饰时，保留真实缺口或在登记前选可执行的设计。

## 持续施工

先清低处障碍并完成地板，再沿可用点击面搭骨架和墙，随后做屋顶、开口与细节。
mc.build 会在同一程序里查询差异、换工作站位、清障和施工；优先使用它完成已登记方案，
不要每放一格都回模型问下一步。支撑和材料有变化后，以新的实际差异决定剩余工作。

一个站位失败不代表整栋不能建。先处理其他有材料、可清理或可落位的格，让相邻结构
形成真实点击面，再重新评估。no_clickable_face 描述当前视线或邻接面，clear_allowed
描述当前施工条件；它们都不是一份给主人签字的新授权。只有服务端实际要求确认时才
按其清单处理；普通草花、树叶和建筑准备不需要模型自行增加询问。

对被模型预算缩成方盒的方案，应在登记前重新考虑体量和细节取舍。当前工具有目标载荷、
支持方块和分页契约，先读 tool_help；不能静默漏掉屋顶、把未指定格当作已验收空格，
或在目标冻结后自行换成更小的建筑。完成时重新核对同一完整目标，诚实报告仍缺的部分。
