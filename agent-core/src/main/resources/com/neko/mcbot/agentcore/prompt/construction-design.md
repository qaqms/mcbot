# 设计并建成一栋能住的房子

把主人给出的用途变成完整的建筑图，再把这张图做完。普通住宅默认按正常可居住的房屋设计，
不是5×5小盒子：外轮廓通常至少约9×11，室内净宽至少7、净深至少9，主要活动区净高默认4至5格；
只有主人明确要求小屋、棚屋或极简建筑时才缩小。普通住宅默认包含实际门、床、工作台、
收纳、照明、窗、完整屋顶和室内通路；主人已要求的内容无需再确认。材料不足就准备材料。
“门洞留了位置”“家具以后再放”都不算这些功能已经完成。

设计前读完本知识的后续页：按 tool_help 回执的 next_name 继续。第一页只够核对要点，
不要只读开头就开始编坐标。先想清楚室内平面、入口立面和屋顶剖面，再写紧凑 regions。

新住宅不默认复用旧任务的房型或恢复图。普通平地先清表土再在同层铺基础：
草方块y=70时，基础方块在70、脚高71；不能把脚高71写成地板71，再直接铺在草地上。
先用普通build_diff核对foundation_surface，出现表土上方待放格的advice时，登记前修正同一候选图。
只清掉短草、花朵不算清表土。主人明确要求抬高或实际坡地需要时才另做有落地支撑的方案。

楼梯的方向在设计阶段就要确定：facing 指向高背，不是朝外的可见正面。
屋脊沿东西向时，北坡各排朝 south，南坡各排朝 north；屋脊沿南北向时，西坡朝 east，
东坡朝 west。每排明确 facing 和 half，图纸 rotation 统一旋转坐标和状态，只旋转一次。
先用 build_diff 的 design_review 核对 stairs_missing_orientation 和 stairs_rising_behind_back：
后者提示相邻上排出现在楼梯背后，坡面可能反了；它不禁止特殊装饰，也不会自动改图。
原木柱 axis=y，东西梁 x，南北梁 z，逐区明确；logs_missing_axis 提示漏写。
rotation 同时旋转轴向，只转一次；旧图不自动改向。

普通住宅先安排足够的净使用空间，再给主体加一处有用途的进退、门廊或侧间。
墙脚、柱梁、窗框和檐口应能看出层次；一圈同质墙加几排楼梯还不是完整外观设计。
主人未要求极简时，平顶方盒、无檐口屋面、没有入口过渡或没有窗的图纸应视为未完成草案，
先改图再登记。设计检查返回compact_residential_footprint、roof_profile_missing、
roof_no_overhang或low_residential_volume时，不能把它们当成可忽略的装饰意见。
窗要有实际玻璃或玻璃板，门廊要有能走到门口的地面，室内工作、睡眠和收纳各有位置。

先做下面五件事，再登记目标：

1. 核对场地和地板高度，选定朝向与实际入口。
2. 安排室内生活区、工作区和收纳，留出连接它们的通路；列出地板、净空、梁灯下缘和屋面最低层的高度，再决定外墙尺寸。
3. 画屋顶剖面，确定两侧坡面、山墙、屋脊与檐口怎样接合。
4. 把门和家具写成真实方块格；最后检查区域叠加有没有把它们覆盖成空气或墙。
5. 用 build_diff 检查整图材料及 design_components。住宅的 doors、beds、crafting_tables、
   containers、lights 为零时，先检查是不是漏写了功能，不要将一个没有门的外壳登记为完整住宅。
   stairs、slabs 是图纸所用构件的数量，不是屋顶美观或封闭的自动评分。
   object_validation.valid 须为 true；false 的 issues 给双格错误坐标和 expected_partner，
   先纠正候选再登记。床头=床脚沿 facing 前进一格，两格 facing 相同，part 分别 head/foot。
   例如床脚 z=9、床头 z=8，二者应 facing=north；写成 south 会把床头指向 z=10。
   INVALID_BUILD_TARGET 表示登记前图纸未通过，可在本任务纠正，不需取消任务或请主人重设目标。

build_diff 核对成功且 draft_retained=true 时，data.target 是完整草稿的短引用，set_goal 直接用它和
target_revision，避免重新展开整图超出参数大小。历史整理后未登记目标的 mc.goal() 为空是正常的，
用 build_record 的 draft_list 找回同任务草稿，draft_query 按16格查细节；design_list/instance_list
只列显式保存的记录。需要跨任务留图，用 design_capture(design_id,target) 保存原草稿再创建实例。
候选与当前 worksite_revision 不同时，先 query 工地；正式登记前且目标格从未改动时，
可用 build_site revise 明确纠正同落点、旋转和格集的属性或材料，expected_revision 填旧工地修订。
临时工程和累计账保持；已登记最终目标或已施工目标格不能走此接口换图。

主人叫停后，执行立即结束。同一会话的已登记长期建筑可由主人明确发送“继续”“继续施工”
或“恢复目标”接回；系统先核同身体、世界、原工地与新权限，保留草稿、临时来源和累计账，
再用原修订重读完整现场，不回放旧程序或路径。不要把前一任务摘要当作当前登记事实。
“目标状态”可查本会话保留资料，“放弃目标”、新普通任务或会话关闭会清除它。
跨重启仍须原持久检查点或已保存的设计/实例；旧包丢失的完整图不能凭哈希恢复。

登记后直接在 run_program 执行 return mc.build()。mc.goal() 可取原 target/expected_revision，
mc.build_diff() 核对原图。不要在每次施工或历史整理后重画房子，修订哈希不是 instance_id。
图纸最多16384个唯一格，可用 regions 紧凑表达；不为旧128格限制把房子缩成方盒。
执行层不会替你发明图中没写的门、床和屋顶，也不会因脚本返回成功就认定整栋完成。

## 由活动空间确定大小

先布置床的两格和床边可站的位置，给工作台留操作面，给箱子留打开与走近的空间，
再从入口画出连续的通路。把家具沿墙组合，避免把工作台摆在中央或进门必经之处。
房间的净面积应在扣除家具后仍能活动；外墙厚度、门廊和屋檐在这之外增加。

没有尺寸要求时，独居小屋可以从净宽五至七格、净深六至九格比较起；这是起草的尺度，
不是固定模板。普通住宅或主人希望宽敞时，可从净宽七至十格、净深九至十二格起草；
多人或储藏较多时继续增加净尺寸或分区。不要只用“五乘五”
代表小屋：五格外宽扣掉两面墙只剩三格室内，放床和工作区后很容易挤成过道。
普通住宅主要活动区默认保留4至5格净高，不把地板厚度、屋顶实体或屋脊总高算进净高。
以整块地板y=0为例，四格净空为y=1至4，覆盖该区的屋顶或梁最低从y=5开始；
五格净空则留y=1至5、顶或梁从y=6开始。有梁或吊灯的位置额外预留厚度，
确保其下方仍达到选定净高，不能先留四格再让装饰吃掉一格。
门本身仍是两格高，门廊和边缘储物区可按用途处理；不能让低坡屋面压住主要生活区或通路。
design_review.volume_height只是整图非空气包围盒高度；地基或高屋脊不能证明室内够高，
无low_residential_volume警告也不代表净高已核实，登记前仍须逐段核对实际室内剖面。

提高净高时同时调整窗的竖向比例、墙面的框架分段和顶梁位置；床、工作台和收纳仍按使用高度布置。
墙加高不等于坡屋顶也按比例拔高：先保住室内净空，再按跨度选择屋面坡度，避免又高又尖的屋顶。
新增的上部空间可以用窗上框、少量梁或沿墙高架收住，主要活动区与通路保持清楚，
不要靠把家具叠高、塞满装饰来填补高度。

从远看轮廓决定主体与附属部分：一个较长的主体加入口门廊、侧边储藏间或退进去的窗区，
通常已有明确主次。扩大的房子应增加可用空间和体量关系，不是把同一个立方盒子放大。

## 地板、门与地形

地板是一层实际方块，身体站在它的顶面。以相对坐标说明：地板位于 y=0 时，普通整块
地板上站立的脚格是 y=1，门的 lower 也在 y=1，upper 在 y=2。墙从地板上开始。
不要在门下再加一层凸起的“门槛地板”，否则室内、门和外侧会差一个高度。

普通平地住宅默认先清表土，再在原层放基础：草地y=70，则地板70、脚高71；
刻意抬高才在71铺板、脚高72。核对support方块y与feet_y，并查看foundation_surface。
图纸写实际替换坐标，施工先挖再放；旧图不临时降锚点，坡地/架空按真实支撑设计。
门外地面低一格时，做真实可落脚的台阶或门廊，不要把“地面高度”直接填成墙底坐标。

入口要形成完整连接：外侧落脚点、台阶、门下半格、室内通路。两格高的通道没有被窗框、
梁、灯或家具堵住。玻璃窗的位置结合室内用途安排，窗台和窗上方保留墙体或框架。
坡地可用不同高度的基础支撑同一地板，或明确分层；四角都应落地，不能一侧埋进山坡、
另一侧悬空。草花、树叶及普通准备障碍按现场清理，不为常规清障另问主人。

开工前查看 build_diff 的 clearing_work：它统计整图已观察到的待清格及相应工具。
成片清土缺铲、拆木缺斧时，先根据现有库存查询真实配方，做够用的工具再施工；
已有合适工具就直接用。执行层会按真实方块选库存中较快的工具，不代替你制作工具。
野花簇和花瓣等薄覆盖物可以按原清障权限处理；清掉下方泥土后它们可能已自然脱落。
若工作导航报告 target_already_clear，重新读原图差异后继续，不再对空气寻找挖掘站位，
也不把自然消失或他人移除算成自己的挖掘成果。

实际门必须写完整两半，不能只指定两格空气。以下是入口部件的表达示例，位置由整栋方案决定：

```json
{"anchor":{"x":0,"y":0,"z":0},"cells":[
  {"x":0,"y":1,"z":0,"block":"oak_door","properties":[
    {"name":"half","value":"lower"},{"name":"facing","value":"north"},{"name":"hinge","value":"left"}]},
  {"x":0,"y":2,"z":0,"block":"oak_door","properties":[
    {"name":"half","value":"upper"},{"name":"facing","value":"north"},{"name":"hinge","value":"left"}]}
]}
```

这段只是门部件，不能单独替代整栋最终目标。放进 regions 图时，先表达墙和开口，
再写门两半；后写区域覆盖先写区域，最后一片空气不能擦掉已经写好的门或家具。
北为负 z、南为正 z、东为正 x。目标 rotation 会同时变换位置和已声明朝向，
不要先手工旋转朝向后再让目标旋转一次。

## 先把屋顶画通

先沿横跨屋脊的方向写出一条剖面，确认每排屋面连到下一排，再沿屋脊方向展开。
住宅屋顶要覆盖室内，封住两端山墙；只放两条檐边、留空中间，或把墙顶铺平，都不能
替代已经要求的坡顶。屋顶伸出墙面形成檐口，门廊可以有较低的附属顶，突出入口。

楼梯 facing 指向高的一侧，双坡屋面的两侧楼梯因此朝向屋脊。半砖 type=bottom/top
决定半格高度，type=double 是整格。相邻两排底半砖如果坐标直接升一整格，会断开；
在剖面里逐排检查接触关系，用可执行的楼梯或整块补足，而不是假定坐标像斜线就密封了。
needs_support 先等邻接施工或搭可回收支撑，再核对；先做内侧屋面，再续悬空檐角。
屋面较宽时考虑较缓的剖面、分翼或错层，不要让一整块宽厅顶变成过高的尖塔。

例如整块地板y=0、主要活动区净高至少四格，屋脊沿 x、从北边负 z 往南走时，一段坡面可以是：
北檐(z=-4,y=5,facing=south)，下一排(z=-3,y=6,facing=south)，再往内升高，
过屋脊后用 facing=north 逐排下降。高背必须对着下一排更高的屋面。
五格净高时相应提高屋面；檐口若在室外，可单独定高度，室内仍按最低顶、梁或吊灯核净空。
这只是剖面示意，不能作为整栋模板；在实际坐标里检查四向、每排高度和相邻形状。
未指定 shape 时由原版依据邻居形成直梯或转角；不要把所有转角硬写成 straight。
half=top 适合特定檐底或装饰，普通坡面用 bottom，避免整片倒挂。

屋面一般是随剖面延伸的外壳，不要在每个高度都铺满向内收缩的大实心矩形，
把阁楼填成多层木块；先明确坡面排、两端山墙和屋脊，再决定局部梁或檐底。
檐口比墙外挑一格时，要让两端和门廊的收边有对应关系，窗的上下框与柱梁对齐。
做较大主体时用入口、偏出的工作区或较低附属顶改变轮廓，避免只是把方盒按比例放大。

把屋面、檐边、山墙和脊线当作不同部分处理。屋面负责连续坡度；檐边控制薄厚和投影；
山墙承接墙身；脊线清楚收住两坡。不是每一部分都必须换材料，但远看要有层次。
深色屋面配较亮墙身容易看清形体，石质基座、木质框架和少量玻璃也能自然分工。
主人明确要平顶时，可以做有檐边、女儿墙或高低变化的平顶，仍须完整覆盖室内。

## 材料与外观的取舍

先选结构语言，再挑现有材料。给主体、一处入口变化和屋顶一个清楚决定，然后在细节上呼应。

- 林间住处：框架清楚、窗区集中，入口有避雨过渡；让梁柱与室内木构接上。
- 田园住宅：较宽敞的生活空间、较低的门廊，工作和储物靠近侧门或附属间。
- 石木工坊：入口宽、基座明确，外墙可显示工作区的大窗和上层储藏。
- 山地住宅：顺坡的基础与入口台阶先成立，再考虑露台、较深的檐和较陡屋面。

这些是设计方向，不是必须照搬的房型或指定配方。按场地、材料和主人偏好组合。
窗、柱和梁有共同节奏，长墙需要入口、窗区或进退打断。用少量材料变化表达结构、
修补或旧化的位置，不要在每面墙随机撒上所有库存材料。
留一两处有意义的细节：门框更厚、窗下有窗台、门廊有柱、侧面有小退台。
选择这些细节时同时检查通行净空和实际放置支持，不能为外观堵住出口。

## 室内要能使用

每个生活层都应安排功能。睡眠区可由床、床边灯和小件收纳组成；工作区组合工作台、
收纳和操作空间；入口附近保留转身位置。较大的房间可以用地毯、半砖或梁分区，
不要把所有设施排成一条没有用途区别的长队，也不要让中央堆满方块。

床必须有 foot/head 两格，facing 从 foot 指向 head，两半朝向一致。head 就在 foot
沿 facing 方向相邻一格。与门相同，只从主格发一次原版动作，消费一件材料，两格都验收。
工作台、独立空箱、木桶、灯笼、火把、活板门、栅栏、墙和地毯可走当前放置链。
箱子只按独立空箱准备，不设计成自动合并邻箱，也不向图纸写容器内容。
其他设施或特殊装饰先查工具支持；无法可靠执行的状态在登记前换成可用构件。

吊灯的 hanging=true 需要上方支撑，落地灯的 hanging=false 需要下方支撑。
活板门用作窗边或架子时，要核对 half、open、facing 与实际原版放置结果，
不能假定执行器会把状态强行写出来。照明先覆盖入口、工作面和生活空间，
再安排视觉重点；悬在空中没有支撑的灯并不是可施工目标。

## 持续施工与收尾

登记一个完整目标，包含必要净空、门窗、室内设施和屋顶。用 cells、fill、regions
三种表达之一；regions 最多128区域，最后写入的同格生效。先看整栋料单再补缺口，
已有材料直接使用，缺床、门或照明材料不能成为从图中省掉它们的理由。

mc.build() 在本地连续查询、换位、清障与放置。默认连续工作，不主动设很小的 max_rounds
让每几格都回模型。它直接返回结果对象，字段不在 data 下；读取 status、goal_satisfied、
placed_blocks、cleared_blocks、remaining、blocked 和 design_components。程序返回成功
仅表示程序正常结束，status=blocked 或 goal_satisfied=false 就仍需处理真实缺口。

最低主体基础未完成时，工作候选和实际批次不抢建新的上层格；必要通路的待补仍沿原修补规则。
blocked=foundation_materials_required 表示基础放置现货耗尽，先读 foundation_work.materials，
核对背包原料，用 craft query=true 查询真实配方。能制作就先按工位、产量及背包空间分批补制，
再用同一个 mc.build() 续建。缺木板现货不代表缺原木，不直接要求主人提供成品，也不重画目标。

放置会封住当前站位最后出口时，would_seal_exit 表示先换外侧站位，再补这格；
不是删掉屋顶，也不是增加一份给主人签字的授权。导航允许已有安全落点的两/三格下降，
