## 实现契约

BuildFoundation从全图最低主体层计算`foundation_work`，独立于候选分页、手距和现货过滤。
主体沿用BuildSite.restorable的普通可恢复整块、玻璃、干燥原版楼梯和半砖分类。
附着件、门床及家具不作为基础门；没有主体格时不引入该约束。
这只约束最低主体基础，不宣称任意多层建筑的所有楼层都必须整层完成。

字段如下：

| 字段 | 含义 |
| --- | --- |
| active、y、total、unfinished | 最低主体基础及从未完成/非待补的未匹配格；没有基础时省略y |
| repairs_pending | 真实来源记录中的通道待补格，仍计入最终原图验收，但沿原修补和出口规则处理 |
| known | 基础目标实态是否全部可核实；未知不能成为升层许可 |
| supply_required | 基础已知且有剩余材料需求，但现货连其中一个基础格都无法支付 |
| materials | 最多8种基础item/required/available/shortfall；其余类型数见materials_omitted |

有部分现货时继续做能做的基础，不要求一次带齐。现货耗尽时mc.build返回
`blocked=foundation_materials_required`，附`supply_required=true`、
`model_reassessment_required=true`及有界基础料单，不触发无关收尾清理。
原模型应先查询背包和真实craft配方，按工位、配方产量及空间制作，再同修订mc.build续建。
基础查询不转化原料，施工器不内置原木转木板或第二套配方规划器。
超过8类时按原完整料单继续查询，不把省略项视为无需材料。

BuildSurvey工作扫描、Lua选格和BuildWork自动/显式页共同限制上层新建。
预留区域及权限复核后，实际放置前再读取基础，现场变更或未知则拒绝过时上层动作。
repairs_only继续只处理原来源待补；需要暂留的通道不强行封口。
原累计账、取消、材料、身体占位、出口、设施、来源和临时回收守卫不扩大。
完整验收仍要求所有原图格真实满足，不以游标到尾、批次成功或动作次数代替。
直接工具反馈和内置Lua投影都保留基础字段，常驻提示及建筑知识同步补制交接。
