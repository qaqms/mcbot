# L2 长期目标跨退出恢复

本卡从已推送的L1 `5381e076e13242bac566afe4cf3ef788c07644f4`接续，
只恢复原长期目标的数据与累计账。主人明确要求恢复后，原runner和loop先核身份、
现场及新任务权限，再由模型选择剩余有限阶段。完整构建、实际XML和候选哈希见STATUS。
本轮不启动K1/P1，不安装或启动游戏、服务器或真实模型，不改无敌。

## 主人入口

在原任务输入中发送以下完整文本；面板、聊天和外部桥共用submitTask，无新增工具或桥字段。
命令去除首尾空白后须完全匹配，仍31项模型工具（22服务端、9本地）。

| 文本 | 行为 |
| --- | --- |
| `目标状态` | 空闲时只读查当前世界、主人、同伴的记录和身份，展示原指令及累计模型步数；不请求模型 |
| `恢复目标` | 空闲时明确消费记录，创建新的传输task_id；先查新鲜身体、原目标现场及新权限 |
| `放弃目标` | 空闲时先确认当前范围，再删除该记录；不请求模型或执行游戏动作 |

进世界、桥重连、身体重建或收到旧回执均不自动唤醒。没有记录、在途标记、
存储缺失、活动任务、身份或现场不可核实时返回明确失败，不把命令当成新的普通模型指令。
外部桥的命令请求与实际恢复任务分别有自己的task_id及终态；恢复命令completed只表示
请求已受理，实际目标仍沿新任务的state/progress/done报告。连接器不得自行重投旧任务。

明确取消、放弃、正常完成/失败、配置重建及普通close清除当前已知范围的记录。
ClientSession.disconnect先停执行并隔离迟到回调，仅保留此前已完整落盘的检查点。
新普通任务在空闲时清除旧目标；没有把任意短任务变成跨退出任务。
只有成功登记lifecycle=long_term的目标可保存；未登记自然语言没有恢复保证。

## 数据、身份与预算

客户端本地`<实例目录>/mcbot/goals`按世界UUID、主人UUID、同伴UUID分别存一条记录。
同一实例才有这份journal；换客户端须另行保留对应数据，本卡不提供同步服务。
原BuildRecords在世界启动时持久化已有world_id，即使尚未创建建筑设计。
写失败保守禁用相关记录/恢复，不中断整个服务器启动。

CompanionPlayer的body_id继续每实例生成，保持S3隔离；新增body_continuity_id保存在playerdata。
普通保存重载可延续continuity，死亡新建身体及显式召唤重置continuity。
旧版本或无效字段生成新值，不能猜测旧身体连续性。恢复必须核同世界、主人、
同伴、continuity及维度，当前存活且环境安全；死亡后不接回原目标。

| 保存内容 | 恢复规则 |
| --- | --- |
| 原goal_id、原始指令、原task_id | goal_id不变，新session/传输task_id隔离旧回执 |
| 初始36槽item/count及坐标/身份 | additional仍用原任务基线，不用重进后的背包重算 |
| 原item或完整building/delivery条件、登记证据 | 建筑须原target/expected_revision，交付须原容器身份和基线，不自动换箱或改图 |
| 原40步上限及已计模型步数 | 等待中的模型轮已扣账，恢复不补；已满足先完成，不再调用模型 |
| 原max_runs、已结束阶段、停滞与重复事实集合 | 重进不清空阶段/无进展账；原上限耗尽且目标未满足就停止 |
| 重复工具、空搜索及拒绝完成计数 | 不因新task_id、换程序或重进获新次数 |
| WorkFailureMemory、DeliveryLedger | 保留真实失败和已核实净搬运账；在途或未知搬运不能生成可恢复检查点 |
| ExplorationRoute | 原锚点、半径、已尝试次数/目的地、访问及地下挖掘/返程账；不恢复短时覆盖有效性 |
| WorkTargets、NavigationTrail、BuildSite | 原工作保护、实际通道、缺口/截断、工地范围/目标/临时位置及原导航累计账 |

空间恢复在服务端新task_begin内重新核身份、实际通道/加载范围、原工地和B4实例修订。
失败即撤销新任务权限，下一次status不能确认有效恢复模式，模型不继续。
工地导航保留原节点、存储、CPU、重规划帽和已消费量，不恢复正在运行的路径或身体工作。
普通单次已终结工具的局部预算仍按原作用域，不把它们改成全局额度。

临时方块与B4自建来源的原生CellWitness不跨重载伪造。临时位置仍占容量并受保护，
恢复时不重新授予清理权；当前块看起来相同也不能证明未被替换。
普通NavigationTrail保留已有缺口与保护，不保证返回路线实际可达或零编辑返程。
短时区块版本、覆盖、活动输入、攻击者、控制/租约、问题/批准、Lua栈、模型流、
旧工具队列与对话历史均不回放。重新观测后只携带原指令、目标及必要事实重新规划。

原read_only保持；恢复autonomous必须同时满足原记录及主人当前开关，不借恢复升级。
服务端须新鲜确认完全一致的read_only/autonomous/confirm模式后才能继续。
原三道闸、身体安全/控制、动作核、有限组合与取消仍执行，不因文件存在而授予动作权限。

## 落盘与保守拒绝

GoalJournal使用有界JSON数据，单条最多512 KiB、128个范围（包括只有标记/临时文件的范围）；
解析前限制32层和100000 token。仅匹配本机制命名的文件计入范围，不删除无关文件。
超帽拒绝新范围，显式放弃删除该范围记录/临时普通文件/标记后可释放容量。
拒绝目录/目标符号链接和路径穿越；客户端本地文件不构成对玩家的安全沙箱或认证边界。
不保存模型配置、密钥、令牌或对话全文；记录包含原指令及游戏事实，按本地数据保管。

保存先强制落盘`.blocked`，再写`.tmp`并强制刷新，通过原子替换生成`.json`；
只在完整结算且新鲜空间事实可用时去掉标记。登记时保持未结算，不能在同轮后续工具
尚未记账时暴露安全检查点。每个工具/组合及阶段验收前先落在途标记；
任何写失败停止并阻止同轮后续动作，不靠旧记录追加预算。
在下一轮新鲜观测、同轮账全部结算且尚未发模型请求时，才再次形成安全检查点。

因此工具、Lua、阶段核验、反问/批准等待或未知效果期间退出，会拒绝恢复旧记录；
不能以“可能没执行”推断重放安全。空间快照超16000 UTF-8 bytes或证据不完整时，
当前原工作可以继续，但该记录保持blocked，不能跨退出恢复。
这种限制可能使长路线或复杂工地不可恢复，不截掉保护集来伪装支持。

文件强制刷新和原子替换不是跨客户端journal、世界和playerdata的崩溃原子事务。
正常断连/退出的受控链路与异常断电、世界回档必须分开记证；本卡不保证后两者一致恢复。
复制存档也会复制world_id/continuity，本卡不提供存档克隆辨别或来源认证。
不同客户端同时操作同一世界/主人没有journal协调或分布式租约，须由维护者避免并发恢复。

容器身份依赖原L1当前原生对象/世界/区块见证，服务器或容器重载通常会失去原身份，
即使同坐标同方块也会拒绝交付恢复；不为提高成功率制造持久容器身份。
建筑修订变化、卸载/不可核实、危险环境、换维度/换身体或耗尽账均保守停止。
