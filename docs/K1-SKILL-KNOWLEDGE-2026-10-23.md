# K1 技能正文按需与实际开销

2026-10-23，源码起点 `54de6ff984c13d1866686db6c7d40056617c5a50`。
最终验收、JAR 与提交以 `../STATUS.md` 为准。本卡只处理知识输入，不修改导航或身体批次。

## 1. 行为与边界

原实现将客户端技能目录的每份 Markdown 正文放进系统提示。
现在常驻的是文件名、短描述、正文修订和可读取名字；需要时通过原 `tool_help` 读取正文。
仍为 31 个模型工具，原参数 Schema 和顺序保持，未增加文件访问工具或桥协议字段。
工具帮助的返回数据增加技能索引/正文分支；工具注册表中的动作帮助继续来自原定义。

启动及每个任务实际开始时，在客户端生成有界不可变快照：

- 普通新任务、已经排队的任务、显式恢复都经过同一开始边界。
- 目录与正文来自同一快照；模型轮次、Lua 调用与上下文整理不重新读盘或换正文。
- 外部修改、人设修改与禁用在下一任务开始生效。需要立即终止当前任务时仍用原取消入口。
- 本卡是模型上下文按需披露；启动/任务边界仍读取有界正文到客户端内存，
  不能称为正文从不预读磁盘，或完全消除本地加载成本。

原模型/阶段/原子调用预算、最终目标、身份、许可和取消链保持。
技能是知识，读取它不执行脚本、不修改世界、不更新库存、不证明目标完成。
Lua 内的 `tool_help` 仍计原调用预算，帮助正文仍展示给模型；不因属于知识就免计或补预算。

## 2. 现有笔记、覆盖与禁用

配置均为当前客户端实例本地文件，路径相对实例根：

```text
mcbot/skills/
  defaults/
    navigation.md
    gathering.md
  navigation.md
  index.json
```

现有顶层 `*.md` 不用迁移。`defaults/` 是可选的本地基础笔记层，本卡不自带游戏知识笔记，
也不从参考项目搬运正文。顶层同名文件覆盖 defaults，按文件名忽略大小写匹配；
同一层出现大小写冲突会明确关闭本次目录，不由遍历顺序决定。
无效的本地覆盖也不会悄悄回退基础正文。

可选 `index.json` 使用结构化 JSON，示例：

```json
{
  "version": 1,
  "skills": {
    "navigation.md": {
      "description": "导航与工作接近时需要核对的现场条件"
    },
    "gathering.md": {
      "enabled": false
    }
  }
}
```

未列出的文件默认启用；禁用同时隐藏两层同名笔记并拒绝旧名字的新读取。
缺少 description 时使用文件名主题，建议为不易理解的文件名补短描述。
只支持 `enabled` 布尔值和至多 160 UTF-8 bytes 的 `description`。
版本、未知字段、重复键或格式错误使整个技能目录不可用，索引保留诊断；
不能忽略坏配置后重新启用本来想禁用的知识。

禁用不删除已经进入历史的旧正文，也不承诺让模型忘记已读信息。
需要清空历史仍走原上下文清理；动作权限始终由原任务/服务端门决定。

## 3. 发现与读取

系统提示始终包含当前快照的技能索引，空目录不增加索引段。
`tool_help {}` 的 `data.tools` 保持原工具目录，并增加 `data.skills` 与 `data.skill_diagnostics`。
每份技能含 `name/label/description/source/revision/body_bytes/pages`，不可用文件另有 `error`。

模型照索引返回的 `name` 调用：

```json
{"names":["<目录给出的技能name>"]}
```

这是原 `names` 字符串参数的已注册知识分支，不是模型可指定的文件路径。
名字由逻辑文件名生成，与机器目录无关；覆盖同名文件保持名字，正文改变则 revision 改变。
不得根据样例自行猜名字。常规工具帮助仍可一次读取 1–3 项；
含技能的调用每次单独读取一页，混入其他名字会明确拒绝，避免突破原回执上限。
同一模型轮仍可发出多个独立 `tool_help` 调用，不强制一页占一个模型轮。

成功返回 `data.knowledge_only=true`、`name/label/revision/page/pages/body`，
还有下一页时返回 `next_name`。照 next_name 继续读取；最后一页不含该字段。
按 UTF-8 code point 切分，每页最多 4096 bytes，连接全部页得到完整正文，
不截半个字符。页边界可能位于 Markdown 段落内部，不能把第一页当作全文。

同修订且正文仍在上下文时复用；整理或清空后缺少正文，就从常驻目录重新读。
没有“此前读过所以永久可用”的隐藏标志；已经被摘要替换的正文不会凭标志假装还在。

## 4. 有界与失败

| 项目 | 限制或行为 |
| --- | --- |
| 文件格式 | 顶层及 defaults 下的普通 UTF-8 `.md`；不执行正文 |
| 单份正文 | 最多 65536 bytes，超限拒绝，不静默截断 |
| 有效文件名集合 | 最多 32 份；两层同名算一份，禁用项仍在发现容量内 |
| 快照正文 | 合计最多 1 MiB；后续超额项保留不可用诊断 |
| 目录枚举 | 每层最多检查 256 条目录项 |
| 设置文件 | 最多 16384 bytes，流式校验固定结构，无任意嵌套 |
| 路径 | 模型只能选择快照名字；文件符号链接及越出根的基础目录/文件被拒绝 |
| 返回 | 一次一页；未知/禁用/坏页号不回显模型传入的私密路径 |

`SKILL_CATALOG_LIMIT` 为发现容量超限；
`SKILL_CATALOG_UNAVAILABLE` 为目录或设置不可读取/无效；
`SKILL_FILE_UNAVAILABLE` 为某篇文件非普通文本、编码/尺寸/总额等不满足；
`SKILL_UNAVAILABLE`、`SKILL_PAGE_INVALID` 为名字或页不可用；
`SKILL_SINGLE_READ` 为技能与其他帮助混读。
这些都不是游戏动作成功、权限批准或可自动吞掉的移动局部失败。
没有通用文件/附属材料读取能力，也不扫描其他实例、宿主或服务器目录。
原生 Windows 重解析点竞态不在离线夹具的实机验收范围，不宣称文件系统对抗隔离。

## 5. 请求体积与发现成本

`tools/FrameworkPerfProbe.java` 使用真实 provider、目录与结果投影，无玩家配置、模型或网络。
4 篇各 16384 ASCII bytes 的合成笔记，总正文 65536 bytes、目录正文 1196 UTF-8 bytes。
旧式全量正文与按需方案使用同一份当前工具表和同一条用户输入，避免将工具说明变化算成收益。
这是知识准备场景的 JSON 字节统计，不是 token、费用、生成速度或整项游戏任务完成时间。

| 合成知识准备策略 | 模拟请求数 | 累计请求 JSON bytes |
| --- | ---: | ---: |
| 旧式全量正文，首次请求即可见全部 | 1 | 108418 |
| 常驻目录，不需要读正文 | 1 | 44050 |
| 常驻目录，读一页后回到模型 | 2 | 92761 |
| 全部页，每页单独回到模型 | 17 | 1381968 |
| 全部页，每轮合并 4 份笔记的独立读取 | 5 | 405580 |

后两行都执行 16 次帮助调用；模拟策略决定 16 或 4 个额外轮次，不是框架强制轮数。
每份后续页的名字来自上一页真实返回，合并策略不猜未来结果。
未模拟缓存计费或输出 token。若任务确实需要全部长文，按需并不保证更快或更便宜。
最直接收益是无关正文不再常驻；实际总收益取决于相关知识比例、复用、发现轮次与缓存。

无技能时基础请求为 42750 bytes；审计基线为 42635，新增 115 bytes 是工具帮助的技能说明。
参数 Schema 合计仍 25505 bytes，31 项参数未改为隐藏或懒加载。
最终探针序列化均值 0.914ms/p95 1.559ms；
20 次读取 4 篇笔记并建索引，均值 4.309ms/p95 7.522ms。
首次同口径目录测量均值 4.013ms/p95 6.344ms；不把复跑当作固定性能保证。
文件缓存、磁盘和同时运行的其他工作会影响结果，未做 JMH 或端到端实机 A/B。

本地证据为 `build/k1-perf-20261023.log` 与 `build/k1-perf-final-20261023.log`，
日志不入仓，关键量已摘录。探针复现方法沿用框架审计 §9；只新建并清理本次 build 临时夹具。
