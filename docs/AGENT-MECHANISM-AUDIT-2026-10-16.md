## 1. 结论与职责

现有方向可以继续：模型根据真实条件选择阶段，Lua组合现有能力，本地有限流程处理
工作集合，身体按游戏刻执行和验证，最终目标另行验收。已有配方、库存、工位和工具
应直接复用；不增加按成品名写死的升级链，也不在模型与身体之间另塞依赖规划器。

主要问题是这些层的事实和生命周期还没有全部贯通：

| 层 | 本体已有 | 尚缺的共用机制 |
| --- | --- | --- |
| 意图与阶段 | AgentLoop、ItemGoal、GoalContinuation；物品数量的同任务有界续段 | 通用建筑/交付验收、跨退出目标恢复与世界身份 |
| 有限组合 | BoundedProgram、Workflow、Gather、Explore、Survey；真实终态、原子调用/时间帽 | 独立身体批次、跨段资源及掉落来源索引 |
| 身体工作 | 原版近身动作、逐刻物理、工作几何、安全采掘、自然拾取 | 统一控制权与可抢占/可重验的恢复契约 |
| 导航 | 工作目标、范围/开路预算、地下短段、特定路标返程 | 完整改后世界搜索、分数脚高、普通移动返程和动态战斗站位 |
| 战斗与自保 | 有界原地近战、冷却/身份/权限/实际伤害；有限水中恢复 | 追击与走位、可信威胁、自卫复用、撤退、完整生存生命周期 |
| 请求与知识 | 早派发、PARK、响应看门狗、短说明/按需帮助、程序查询本地使用 | 技能正文按需读取；完整Schema仍常驻 |

应继续让短任务和长期阶段走同一动作与事实入口。阶段越长不应意味着更多专用工具、
更大模型步帽，或在失败后重开原范围、探索账和许可。

## 3. 本轮落地：任务内失败账

`WorkFailureMemory`放在agent-core，AgentRunner在所有远端原子工具的实际发送前
统一检查，在匹配的tool_result或job终态记录。直接调用、不同Lua、workflow、
gather/explore的原子子调用及同task_id长期阶段因此共用同一份证据。
这是现有事实/预算职责的延伸，不是从参考移植的失败缓存或新的规划层。

契约：

1. 只跟踪move_to/break_block的明确局部失败，以工具、结构化参数、原因类别计数。
   JSON键顺序及数值1/1.0相等，耗时文字不参与键；参数在记录时复制。
   同一类别五次真实失败保留原回执，第六次以`REPEATED_FAILURE:`拒绝派发。
2. job_ack、progress、重复/迟到包、本地超时及取消补账不计入真实终态。
   原失败与部分效果不改写成成功，不因加账本丢掉原data或重放动作。
3. 成功details状态只有完整36槽、维度及有限坐标的事实变化才失效旧证据。
   首次状态仅建立基线；不完整状态、同一脚格内微移、时钟、血量、换槽及耐久
   不清账。物品按总量汇总，不把背包槽位重排当进展。
4. 真实原子挖除/清障/放置、制作、拾取、装料/取料及搬运计数也可失效旧证据，
   包括失败终态中的已发生效果。查询的假设产量、成功空动作、组合累计actual_progress
   不清账；不能让同一段累计成果被反复用于刷新尝试次数。
5. 最多128条，不淘汰旧条目来补次数；满账时工作动作返回`FAILURE_MEMORY_LIMIT:`，
   查询及其他能力仍可用。拒绝附`data.failure_memory`的原因、次数、上限及
   `dispatched=false`。这种本地拒绝不属于try_call可继续捕获的局部路径失败。
6. 新任务/身体替换/会话重载不沿用旧账，长期阶段不重新建账。
   旧身体排队动作拒绝发送，旧身体终态不能清空或污染新身体的账。
   既有Lua新鲜状态门、权限、调用/时间/输出/计算帽和取消继续生效。

边界：这是相同参数的任务内止损，未归并相邻目标或省略/显式默认参数等语义等价调用，
不是世界可达性索引。真实位置/库存变化会使旧证据失效，往返旧位置不保证保留历史；
其他玩家改变地形但身体事实未变时，当前没有世界编辑事件来自动解锁旧失败。
范围覆盖、搜索失败类别、局部地形变化与资源索引仍须连同后续导航卡完善。
拒绝一次调用不代表整个长期目标已验收，也不自动提高或重开任何预算。

## 4. 战斗与自保必须一起设计

已核参考链路：`task/chain/MobDefenseChain`、`FleeChain`、
`task/combat/AttackCompanionTask`、`combat/AttackPlan`与`CompanionBrain`。
本体对应`AttackTool`、`EntityAttack`、`CompanionScheduler`、
`CompanionPlayer`、`WaterRecovery`。现有attack仍是固定目标、最多10次/400刻的原地近战，
没有追击。hurtServer覆写只是生命诊断，没有受击抢占。

后续战斗卡须完整包含以下关联机制，不能仅增加自动attack调用：

- **一个身体控制入口。** 明确危险反射、有限工作和空闲动作的优先级及租用范围。
  切换时释放移动、手部使用、导航和挖掘裂纹；非获胜工作不能仍向身体写输入。
  当前水中输入覆盖和任务槽互斥不等于通用抢占器。
- **共用战斗执行器。** 模型指派战斗和自卫调用同一实现。自卫层识别何时需要保护，
  不再维护一份选武器/挥击/追击逻辑；否则移动和蓄力会互相打断。
- **可信威胁及权限。** 区分附近生物、实际锁定本体或近期施伤的攻击者；
  核对来源时效、UUID、维度、存活及新目标许可。命名/驯养/主人等保护不得被
  “自卫”绕过，不能把路过的中立生物自动招惹进来。
- **局面、承诺与迟滞。** 一次刻内读取共用战场快照；保留有效目标、路线和安全站位，
  只在失效或更急危险时切换。移动目标满足的原版碰撞箱/视线/距离须与出手一致；
  挥击和走位可以同刻推进，不因“正在靠近/后退”而停止合法还击。
- **撤退也是独立身体需要。** 用有效生命、防护、可用武器及真实追兵判断；
  选定稳定避险落点，有界重规划和无路退让，防止每刻改方向绕圈。
  原生伤害、爆炸、弹道和怪物差异要有对应事实，不能照抄参考阈值或无期限预算。
- **抢占后的结果和恢复。** 受击/入水不等于主人取消，取消后不得自动恢复；
  恢复前重查目标、位置、主手、材料、许可和地形，已完成挖放不重放。
  需要同时设计服务端有效执行刻数及客户端等待/墙钟帽，不能只冻结一边造成假超时。
- **终态与生存边界。** 命中、实际伤害、目标丢失、受保护、撤退、受阻、未知效果
  分开结算。氧气/伤害/食物/装备/死亡与重建是另一完整生命周期；
  本轮保持原无敌设置，不用放开无敌来冒充自保实现。

最小验收链应包含：工作中受袭→唯一控制者→同一战斗控制器→威胁消除或安全停止→
新鲜重验剩余工作；穿插主人取消、身体更换和维度切换，不得自动续跑旧目标。
远程武器可分后续卡，但接口和状态不能预设只有原地近战这一种行为。

## 6. 长目标、知识与执行位置

参考`agent/.../goal/GoalSteward`把阶段终止、身体有限任务、取消、续跑和目标保存关联起来；
本体当前数量型长期目标可直接用新鲜背包核验，已有同任务阶段帽/模型总步帽/探索总账。
应学习事件驱动和恢复时效，不为确定数量验收再引入每阶段额外模型裁判。
通用目标需先定义可验证条件；模型一句“完成”不能代替建筑状态或容器交付证据。

跨退出恢复须绑定世界/主人/身体、原目标与基线、累计预算、停止意图及待核对效果，
启动后先观测再决定剩余工作。不得重放在途动作、恢复旧实体编号或沿用失效许可。
目标恢复和身体有限任务恢复也不能各自重开同一工作。

参考`api/agent/skill/SkillRegistry`采用目录发现与正文按需读取；
本体tool_help已实现，但全部24项参数Schema和技能正文仍常驻。
下一步要先量正文体量/实际使用，再实现稳定索引、读取边界、覆盖/禁用、
加载失败反馈和上下文整理后的重新发现。只删定义会把节省变成参数猜测。

参考`docs/shell.md`的执行靠近身体还关联主线程预算、任务归属、调用权限、模块版本、
取消与结果帽。本体现Lua在客户端运行，身体操作在服务端逐原子结算。
不能只把脚本搬到服务端而遗漏这些边界；应先测逐格网络/调度是否为实际瓶颈，
再考虑独立身体批次，保留按格活世界复核和不可逆效果账。

## 7. 分卡顺序与协作边界

1. 本轮任务内失败记忆，先完成真实终态接线和离线边界验证，见STATUS。
2. 按日志复现工作导航/坑内触碰、编辑后地形与搜索费用；连同掉落来源/合并证据
   分卡推进，禁止把预算加大当作路径修复。
3. 身体控制权与抢占契约，再让主动战斗和受击自卫复用同一控制器，
   连同可信威胁、稳定追击/撤退和恢复验收，不并列写第二套自动攻击系统。
4. 根据实际输入量补技能正文按需读取；通用目标验收及跨退出恢复另开生命周期卡。
