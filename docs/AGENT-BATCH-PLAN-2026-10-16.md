# 共用能力与建筑的分批计划

状态：N1/C1/F1已实现并完成离线验收，其余19卡待实施，下一组优先N2a→N2b。
规划源码基线为b05e5a4；当前1171项离线证据、候选与实机边界见`../STATUS.md`。
本文是下一批的施工依据，不覆盖历史证据，也不把参考项目已有能力记成本体已有能力。

## 1. 固定职责

- 模型从实际库存、配方、工具、工位、地形和风险中选择当前阶段；条件已满足就复用。
  Lua组合既有能力，局部有限流程处理工作集合，身体逐刻执行，最终条件独立核验。
- 短任务、长期阶段及身体持续行为共用动作实现、事实来源和结果口径。
  持续行为只改变触发、休眠和结束条件，不另写一套走路、挖放、攻击或拾取。
- 不按成品或建筑名称写死升级链，不增加材料依赖求解器来替模型选择阶段。
  建筑目标格排序、有限候选选择和支撑检查属于已选工作内部的执行前提，
  不扩展为自动采集、合成、补给和换目标的第二个规划系统。
- 原模型步帽、任务范围、探索账、许可和取消保持。换Lua、换阶段、抢占恢复、
  建筑续批都不能重新获得预算。新增能力须声明自己的有限上限及累计归属。
- 只改mcbot；宿主、协作者连接器、参考副本与玩家实例不改。参考只读学习机制，
  不复制或翻译代码、注释、提示词、技能或文档正文；不自动安装或启动游戏/真实模型。

`docs/build-designs.md`记录过有名设计与命令编辑方案，但当前`Design`实际是格集或蓝图句柄，
`BuildApi`/`BuildOps`/`modules/build.lua`才是本轮核对到的执行链。旧cli附录也包含多次变更，
不能据旧设计稿断言现有命令库仍可用。本体将可复用设计作为自己的后续数据能力，
不复刻旧命令系统。

还须明确以下差异：

- 参考部分方块直接写状态并在收尾集中更新，本体保留原版BlockItem.place、真实接触面、
  状态/消费/多格副作用核验；不支持的目标如实报告，不为还原蓝图绕过规则。
- 参考有把跳过格排除剩余工作、收尾报告世界改变的口径。本体允许有限批次正常结束，
  但整项建筑是否满足必须查真实状态；跳过、未知、损毁和不支持格不能悄悄变成完成。
- 参考实例主要按图名/维度/锚点识别；实际Site判断与部分说明对朝向身份的叙述不一致。
  本体使用显式实例身份和目标修订，朝向/尺寸改变是一次可审查修改，不能误认另一栋。
- 参考蓝图与直接格集的缺料策略不同。本体先做明确边界内的有限工作集，
  需求/可用/已分配/已消费分开；全量需求可分页查完，不靠失败回执才发现缺料。
  中途库存变化保留真实部分效果；缺料交回模型决定下一阶段，不由执行器自动找料。

## 4. 建筑各卡必须覆盖的关联机制

### B1：表达、对账与材料

先支持已选工地的有限格集、线/面/分层等可组合数据，参数化形状仅生成目标，
不自行决定建什么房型。原点、旋转、目标修订和明确的空气/未指定格语义要固定；
未指定格不动，清空须是显式修改并走挖掘许可。
已有方块直接复用；目标状态分作者要求与原版动态状态，区分缺失、未知、不支持和冲突。
任何替代材料或放宽匹配都须显式登记，不能为通过验收临时忽略朝向、数量或部件。

料单从同一实际可执行放置规则派生：普通物品数量、多次放置/双层、多格主次部件、
组件要求、返回物和已有满足格分别处理。为当前已选工作做有限材料分配以防重复承诺，
不是自动跨工艺依赖规划。全量需求与本批需求分别给出；阶段选择继续由模型按库存/
真实配方/工位补缺，不内置小屋、工具或矿物采集链。

### B2：有限工作与实际完成

在当前位置处理有界候选集；不足支撑的延后，保护/界外/未知/不支持单独返回，
不以“剩余可做为0”冒充所有设计格满足。查询和执行共用可施工判据，
执行前仍复核材料、实际面/落点、占位、原许可、身体控制权和区域锁。
单格工具、路径垫块与建筑使用同一放置核心；建筑目标状态要求是该核心的受限扩展。
朝向/上下半若原版动作无法产生，明确受阻，不直写或反复拆放。

每格记录消费、实际受影响格和失败部分效果，门/床不能重复收费或越界写另一半。
世界自然更新后用有界新鲜扫描验收；朝向错误、部件丢失或外力损毁要如实留缺口。
支撑先后与预算属于局部工作顺序，不推导无限施工依赖树。
扫描、执行和最终核验都须有CPU/格数/总动作/时间帽；大图分页不能漏页。

### B3：多站位、工地保护与临时支撑

Lua根据差异选择当前能完成的一小段；既有move_to/BlockMining/BlockPlacement执行，
不把寻路/挖掘/采集重新写进建造器。局部移动失败只在原try_call条件允许时读取，
重查事实后按原预算选择下一段；缺料、许可、安全、未知、取消仍停止。
无进展、往返同站位/同缺口及重复同修订检测不能只看本次数字是否变化。

规划与活体执行都保护当前目标、已建成品、工位和承重/进出通道；
不能一路拆墙再一路补墙。临时工作台、脚手/垫块有单独实际来源和用途记录，
未确认依赖解除前不回收；受击撤退也不能通过挖成品抄近路。
检查支持关系只是有限空间工作，不等于承诺任意建筑结构工程或自动找料。
遇实体占位先报告/有界让位，不能擅自攻击或搬走玩家。

### B4：设计复用与实例事实

可复用设计保存目标数据，不保存能绕过权限执行的脚本。使用稳定标识与修订，
逐步编辑、概要/切层分页展示，避免一轮输出整栋或每轮塞整张蓝图。
实例绑定世界、维度、主人与工地，另记设计修订/锚点/朝向及实际施工记录；
设计变更不会无声修改已落地建筑。

修建从真实世界差异出发。拆除旧格需实际来源可证、当前状态仍匹配、无外部改动冲突，
再经原许可；只有相同方块种类不足以证明仍归本次施工，无法区分的同块替换保守冲突。
已满足但非本体所放的格不能顺手认领成以后可拆。
每个真实动作及时记账，取消/断连保留部分结果；重启核对差异，不重播旧动作。
记录落盘不等于自动恢复目标，L2前只允许显式新调用按现场继续。

### B5：格式和复杂对象

一种导入格式独立验收后才扩下一种；先普通方块，再带状态/多格，
最后按需求做装饰组件与摆设。所有来源转入B1同一目标表示，
没有蓝图专属的宽松放置或另一套材料计算。
名称/目录解析、压缩大小、解压后大小、尺寸/坐标、格数、调色板、
嵌套深度和处理时间均须有界，不能照搬参考无限NBT分配。

容器内容、战利品、命令、交互执行载荷及任意实体不随图导入；
