## 一、同层多目标

### 参考观察

调用链为common/task/build/BuildSurvey.tally →
BuildCompanionTask.endPass/tickWalk → Arrival.place →
task/move/Destination.cells → pathing/search/Goals.AnyOf → AStar → drive/Arrival。

施工收遍后先看真实动作数与满足格变化。有可做近身工作就继续施工；
需要移动时取待做远格中的最低层，将该层多个格交给同一次导航。
Destination按出发位置排序，一般最多取64个成员，构造成一个组合目标。
这是单次目标集合的计算规模约束，不是任务尝试次数或整趟搜索总限额。
到位后重新开施工遍历；移动本身不证明产生了施工进展。

AnyOf的各个接口一起组合，不能只把“到达”改成逻辑或：

| 目标部分 | 组合含义 |
| --- | --- |
| contains | 身体满足至少一个成员 |
| estimate | 各成员估价的最小值，指向集合中的可选终点 |
| arrival | 只在当前站位满足的成员中比较到达后工作费用 |
| endCells / heights | 取所有成员可能终点的并集；无有限界的成员不能被悄悄裁掉 |
| protection | 保留所有成员的规划保护 |
| sight | 根据当前满足成员决定；参考的通用组合并不等同于严格物品放置接触选择器 |

AStar考虑路线费和到达费，不把几何上离哪个格最近当作最终选择。
对于有到达费用的站位，它先把工作费加入优先级，再与其他路线比较，避免起点已经
够到一个很昂贵的成员时直接结束搜索。
另有专门的DigAny，会计入各矿格采掘费用及可触及成员数量；普通Place的AnyOf没有
这项矿簇偏好，不能宣称参考放置已经最大化了每个工位的施工覆盖数。

参考Goals.Place仅要求手距和身体不占格，相关施工有直接写世界路径。
本体必须用真实轮廓、点击面、原版预测状态及原图约束判断每个放置成员，
不能为方便多目标组合而采用参考的宽松放置到达判据。

### 本地接入

当前construction.lua在扫描结果中选一个far，move函数携单个work_target/place_item；
MoveToTool、PathTask、PlacementWork和LevelDigSampler也都围绕单格工作意图。
NavigationGoal还没有组合目标，BoundedProgram.helperData会压缩施工内部成功回执。
因此仅新增一个anyOf算法方法不能完成接线。

需要贯通的具体约束：

- 从同一原图修订、同一施工阶段的最低可做层取得有限候选，先过滤缺材料、缺兼容点击面、
  未知及权限阻塞。待补格保留原repairing阶段语义，不与普通阶段混选。
- BuildSurvey当前work_scan每次只交有限详情并携游标；选目标不能把当前页误当作
  全层全部候选。候选截取、顺序与续页必须明确，不在Lua累积整份大图。
- 所有成员的实际工作判断使用同一假想站位与同一TerrainEdits。不能把A成员的距离、
  B成员的点击面、C成员的材料拼成一个不存在的可执行终点。
- 一个成员已完成或锚点消失时，重评该成员；其余成员仍可做就继续组合导航。
  取消、任务身份失效和权限撤销仍作用于整趟，不能被成员退让吞掉。
- 路线不能往任一待放目标格垫脚手架。未来尚未建出的整个设计仍不能冒充当前碰撞；
  对实际待清理的目标也不能因为保护集合扩大而阻止原授权清理。
- 终态记录同次搜索的候选集合身份、实际落点和现场可做的成员。PlacementWork.finish、
  Lua成功回执压缩与后续build_nearby必须理解这个结果，不能仍复核入参中的第一格。
- 到位先重扫近身工作，真实施工后才更新进展。全部成员不可做时给出成员原因，
  不能把导航成功当成一层建好，也不能因一个坏成员无休止占住整趟。

## 二、跨段学习

### 参考观察

调用链为AStar.Pass记录展开边 → learned → Learning.raise →
SearchResult.raised → Driver.poll → TripMemory.raise/frozen →
下次Search.remembering → Estimate.at。执行失败另经Driver.fail写入TripMemory.block。

它保留两类不同信息：

| 信息 | 内容与作用 | 生命周期 |
| --- | --- | --- |
| 估价增量 | 已搜索区域通向边界的额外代价，下一次搜索避免继续优先钻同一死角 | 当前目标相关；retarget清除 |
| 受阻步骤 | 走法种类、起点、落点组成的一条有向步骤 | 当前导航趟内保留；换目标不自动清除 |

学习计算使用搜索实际接纳的边及费用，从未展开边界向已展开区域反向传播最低代价，
边界保留原估价，内部只提高不降低。完全穷尽且没有未知出口的区域才可能得到无穷估价。
例如一个区域的唯一出口当前估价为6，走到出口至少再花4，内部原估价为1，
就有理由把该状态的估价提高到10；提高来自已搜索的边，不来自失败次数。

未知边界是关键：AStar把读到未加载列的节点标为holed，学习时仍视作边界，
不能把“没有读完”写成“无路”。预算耗尽、未加载、全部穷尽、起点不能站和取消分别结算。
同坐标有多个节点时，参考learned取观察到的最小增量，包含未展开变体的零增量，
避免最坏的一种身体/预算状态给其他状态强加同样的代价。

Driver收到无路线结果后，只有确实获得学习更新且停因允许时才继续搜索；
穷尽、起点无效或没有新信息就结算。若提前搜下一段发现预计段尾是死路，会在进入前重规划。
能交半程时还要检查可逆性与安全停留条件，并非只看离目标更近。

这和本体continueSearch保留同一个open/best并扩展下一批不同。
前者将一次搜索结论传给后续搜索；后者继续同一份尚未穷尽的搜索。
保留frontier有价值，但不能因此宣称已有跨段学习，也不应为模仿学习而每批丢弃现有frontier。

### 本地接入

本体有两个必须先处理的差异：

1. DigAStar.h含加权和ApproachEstimate引导；ApproachEstimate.cost明确不保证最优下界。
   不能把这个排序值直接喂给学习，再将提高后的数当成不可达证明。
   可证明的基础估价、学习增量与额外排序引导必须明确区分，旧路折扣也要按相同费用口径处理。
2. 本体State由坐标、挖掘数、放置数、完整累计TerrainEdits区分；
   同坐标不同编辑历史可能是有脚手架/无脚手架、有净空/被方块占位的不同可达状态。
   不能直接按坐标把某个分支的无穷估价覆盖给全部状态；只对已观察变体取最小值，
   也不能自动证明未观察编辑历史同样不可达。

接入应从同趟、同目标、前提稳定的状态开始，明确哪些状态可以共享记忆；
不能证明可共享时，降级为排序提示或不复用，不作为剪枝与无路证明。
被存储整理丢弃的节点或未完成前提评估同样不能当成穷尽边界。

本地失效契约需要覆盖任务epoch、身体/世界、目标集合与修订、路线范围/编辑许可、
真实相关地形、工具效率与耐久、材料和待补义务。补了工具、建出支撑或获得新许可后，
旧的高成本/死路结论不能永久保留；这比参考仅按同趟保留受阻步骤需要更谨慎。
记录受阻时区分方向、走法、真实前提失败及依赖，不能扩大成整列或整片禁区。

搜索结果带原目标与前提版本，采用路线和合入学习分别检查。
旧搜索在目标变化后迟到，即使某条路线还能作为接近前缀，也不能把旧目标的估价增量
混进新目标记忆。工作线程只读冻结记忆，世界线程接收有效结果后写入；取消不写回。
内存保护仍有必要，但不能通过偷偷恢复默认整趟节点/时间/次数帽来代替学习。

## 三、复杂编辑后台化

### 参考观察

调用链为CompanionPorts/GateTerrain → Driver.dispatch →
WorldSnapshot + CostModel + Search → Searches/Pending → AStar +
EditedView → Driver.poll → Step.recheck → 实际输入与Mouse → EditLedger。

它不是只有一份方块快照：

| 数据 | 实际做法 |
| --- | --- |
| 世界 | 世界线程复制已加载非空区段调色板、边界和维度信息；不为搜索加载缺失区块 |
| 读取缓存 | WorldSnapshot按需解码层与格标志，正确发布只读数组；未知列另有显式标记 |
| 身体与工具 | BodySnapshot复制背包和相关身体属性；ToolChoice据此估价，搜索不读活身体 |
| 许可 | Gate保存规则、模式、任务授权；TerrainPolicy只能读传入视图和线程安全数据 |
| 来源 | PlacedBlocks按区块写时复制发布，允许后台读；它是共享的并发来源索引，并非整次搜索绝对静止的来源快照 |
| 材料与危险 | 组CostModel时读取当前可用垫路材料和威胁，再供该次搜索定价 |
| 预测改动 | EditedView在底层视图上叠挖除、支撑、门状态等；不在预测时实际编辑世界 |
| 接续起点 | Search.after携上一段末步的落点状态、编辑及呼吸信息，避免快照尚无未来支撑时误判起点 |

因此“线程安全”和“所有事实来自同一时刻”不能混称。参考来源索引靠并发发布保证读取安全，
动作发生前仍有现场权限核验；本体不能仅冻结区块后继续在后台访问BuildSite或活背包。

参考搜索的编辑历史也有明确近似：AStar.HISTORY为8，展开时只叠最近8个父链节点的编辑；
Nodes身份按位置、可选改动计数与呼吸档区分，没有把完整编辑集合纳入节点键。
EditedView中的持久共享减少的是局部改动表复制，不能据此宣称参考搜索保留了完整历史。
这与本体完整累计TerrainEdits不同，不能为了性能直接裁掉历史；回到旧脚手架、
螺旋清障和恢复原图都可能再次依赖较早编辑。

世界线程在派发前取数据，工作线程独占搜索，结束后发布结果；排队和运行时间分开测量。
Pending.cancel移除排队项并通过取消标记让在跑搜索退出。
Step开始时重新组实际成本模型，用原动作前提复核现场，实际账只收原生动作结果。
Continuation按剩余运动时间启动下一段，并在段尾前等待下一段明确；
等待位置避开不能释放输入停留的攀爬节点，失败时才回到身体当前落点重新搜索。

### 本地接入

本体NavigationSnapshot已经复制区段，但DigSampler在该视图中的挖掘费为不可行、
放置为false、库存为0，目前适合无编辑路线。
PathTask.newSearch还显式跳过活动工地与额外步骤约束；PlacementWork.goal没有冻结实现。
LevelDigSampler持有ServerLevel/ServerPlayer，BuildSiteAccess持有CompanionPlayer，
BlockPlacement.PlayerAccess建立带玩家的BlockPlaceContext，并查询实体、权限与原版生存条件。
这些是实际阻断点，删掉后台分支的条件判断不能解决它们。

应在现有组件边界分离纯事实/预测与现场效果，至少覆盖：

- 工地修订、目标约束、通道/范围、工作保护、临时来源、待补和累计补料义务的数据副本；
  不能把CellWitness、活区块、BuildRecords或身体对象塞进后台闭包。
- 工具/库存/状态组件、身体尺寸与手距、步高/安全落差、冻结许可、实体碰撞样本及未知标记。
  有限实体样本是计划前提，执行仍要重新检查真实实体。
- 真实点击锚点、累计编辑视图、预测落位、轴向/朝向/半砖/楼梯邻域、局部出口与站位碰撞。
  SupportPlacement虽已有纯访问器入口，生产prediction/admissible回调仍读live身体与世界，
  不能只换底层BlockGetter就称为完全后台化。
- 无法脱离原生上下文可靠预测的方块保留明确的现场检查边界或继续使用原线程路径；
  不假造LevelReader，不直接写最终状态，不把邻域不确定简化成可放。
- 接续保留本体remainingEdits、材料/挖掘预留及整趟实际账；新段不能重复花尚未结束的原段材料，
  也不能把预测编辑提前记成真实repair_pending或来源。
- 搜索、目标、前提、路线代际与取消身份一起发布。采用前按真实落点、路线清单、
  当前许可和材料复核；不要求每次无关区块更新都推翻全路线，也不接受已经失效的相关前提。
- 一个DigAStar实例只能由一个线程推进；主线程接收时必须确认工作线程已结束所有权。
  队列满、异常和取消均释放输入与快照，保持当前有界线程池/队列，不照搬参考的无界队列。

## 关联验收场景与实施顺序

以下为待实施验收要求，本轮没有新增或执行这些测试。

| 场景 | 应证明的行为 |
| --- | --- |
| 同层A无路、B有真实点击工位 | 一次组合搜索找到B；不先耗尽A的整趟 |
| 低层远、高层近；候选跨页 | 全目标语义保持，不因当前页或手距抢做高层 |
| 不同材料/轴向/face成员 | 只允许同一成员的完整原版前提，禁止拼接条件 |
| 一个成员被玩家补完/拆锚点 | 退让该成员，其他可做成员保留；最终重验原图 |
| U形死角、同前提再次搜索 | 学到的新代价影响下一段；未加载出口不记无穷 |
| 同坐标不同编辑/材料历史 | 无支撑分支的失败不污染有支撑分支 |
| 改目标、换工具/许可、地形开门 | 对应旧学习失效，迟到结果不混入新版本 |
| 前段未落地支撑、超过8步回访 | 下一段可用完整累计预测；不能因截短历史制造假地板 |
| 后台快照后玩家改墙/实体占位 | 计算不读live对象，采用前与执行前分别重查 |
| 取消、队列积压、错误落点 | 无迟到动作/学习；快照释放，实际效果不被清零 |
| 脚手架拆降与原图修补 | 原材料、来源、冻结修订及补料义务全程保持 |

建议按依赖分别实施并验收：先贯通同层多目标与原版工作终态，再在清楚的状态/代价模型上
建立同趟学习和失效机制，最后扩展严格工作目标与累计编辑的后台数据边界。
后台化本身不会修复不可满足的工作目标，学习也不能替代原生放置前提。
参考相关Goals、Learning、TripMemory、SegmentSearch、SnapshotAndDispatch、EditedView和
Continuation测试已作为源码证据对照；没有移植其测试实现或宣称参考测试在本机已执行。

本轮结论是接入设计已细化，三项生产能力仍未完成。现有可安装候选继续以上轮STATUS为准。
