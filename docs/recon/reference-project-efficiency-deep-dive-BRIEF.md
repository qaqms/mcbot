## 1. 往返经济学

- **主请求 18k–33k token**（38 工具 schema + 系统提示 + 全历史）；长期目标硬线 **30 轮**（≈60 万 token 起）。
- **无工具回合上限（有意）**：曾有的"同签名重复调用"检测器把**正确的超时重派**误杀，故移除；失控交给主人中断 + 目标轮数。
- **一次响应批多个动作**：响应里的工具调用整批交给派发器，派发器**严格串行单槽**（`inFlight` ≤1）逐个跑。
  省掉"一个动作一次往返"的放大效应。⇒ 也是它**必须**把无界长活做异步的原因。
- **派发器在飞兜底 15 分钟**（注释：只救死服务端）。⚠ **但只在客户端 tick 里被检查**——无 tick 则永不触发。
- **收尾顶替往返**：任务完成走事件，且按队列三态路由自动落进"立刻开轮"档 ⇒ 不是新增开销，而是**替代**旧同步模式的最后一次结果往返。
- **禁用轮询**：提示词+回执措辞双处强制。⚠ **只有提示词级强制，无运行时冷却**——反复调状态查询不会被挡。
- **替换式受理省一轮**：注入的 `<current_task>` 明确说"直接派新活顶掉旧活，不必先 stop"——
  说成"别再派"会让模型先 stop 再派，**白跑一轮**。
- **目标评估器 = 另一次便宜小调用**：无工具、无人设、无历史；窗口 **8000 字符**、每行 **400 字符**；只把 fresh token 入账。
- **目标正文只说一次**，之后每轮只补一句"还差什么"。成本模型写在注释里：历史每轮全量重发 ⇒ 每轮重发目标正文是 **O(n²)**。
- **每轮一次重试**：传输层自己退避；回合层只在"流中途死亡"时重跑**一次**整轮（响应落地即复位）。
- 压缩调用同样烧 token，计入累计。
- 传输层：连接超时 **10s**、请求超时 **120s**（仅覆盖到响应头）；重试 **2 次**、退避 `min(500ms×2ⁿ, 8s)`、
  **抖动为减去最多 25%**；`Retry-After` 仅在 ≤60s 时采纳；可重试 = 408/409/429/5xx 或专用头覆盖；
  **重试只在首个 chunk 送达之前**；**SSE 块间空闲看门狗 90s**（单守护线程，每 15s 巡检一次）。
- 外部脑通道：控制超时 10s、事件长轮询默认 2s / 上限 50s、16 线程池。

**⇒ transferable to mcbot:** (a) 一次响应批多个动作 + 逐条串行执行（mcbot 已有三道闸，天然可做）；
(b) 长活"受理即回执 + 收尾走事件"；(c) 判定类调用独立成便宜小请求；(d) **保留早派发**——参考项目没做，mcbot 已领先。
mcbot 的桥线程池 8 已被标注"每 SSE 永占一线程"，与参考项目的"控制/长轮询分档"对照可减压。

## 2. 提示词 / 缓存经济学

**稳定层（进系统提示，必须逐字节稳定）**：人设 + 操作核心（静态常量）+ 技能目录 + 本能名册 + **延迟工具目录**
（每工具一行摘要，**上限 96 字符**，取描述第一句）。
- **恒定排序是硬要求**：目录"两次生成必须逐字节相同，否则前缀缓存白瞎"。
- **工具 schema 是缓存前缀的一部分**：常驻 9 个（目录检索/技能加载/待办/自身状态/单格探测/观测网格/两类扫描/寻路），
  **其余默认延迟**，模型调目录检索工具才取回完整定义——"省的是每一轮的输入，不是一次性的"。

**刻意排除在系统提示之外、改按轮注入**：
- `<known_blocks>`（已用/已放的工作站）——理由：随放置变化会打碎前缀缓存。
- `<runtime_state>` 信封 = `<current_task>` + `<inventory>` + `<effects>` + `<riding>` + 插件每轮片段；
  全部现算，**一个字都不入历史**。
  - 效果块理由最锋利：带倒计时，沉进历史后十轮读到的是"一个理直气壮的错秒数"。
  - **空块不发**："空块也是要读的 token，而'没写'和'写了没有'对模型是一样的"。
- **背包块是为了省一整轮**：注释写明"放进请求而不是让她调自身状态工具，省的是**一整轮**（请求+结果+再请求）"。
  合并同类计数、不报耐久附魔（要精确到槽位另调界面探测）。
- 背包块有**身份缓存**：只在收到**新快照对象**时重渲染（比对象身份，不用时间戳凑版本号）。

**缓存浪费诊断器（逐轮计算，不是统计）**
- 定义：**漏掉的 = min(上轮提示词, 本轮提示词) − 本轮缓存读**。
- **噪声底 1024 token**；三种情况不计：无上一轮、本轮无提示词、
  **本轮完全无缓存活动且此前也从未有过**（区分"没命中"与"这家不报缓存"，否则后者每轮都被判全量漏）。
- 历史被剪断（压缩/清空）后 **reset**，下一轮重新起算。
- 刻意**不折算金额**；**累计式不存历史**（只需上轮体量）。
- 官方单测钉死判据（含"从不报缓存的服务商不被指控"用例）。

**用量四元拆分**：`input` / `cacheRead` / `cacheWrite` / `output`，三者相加 = prompt；
**fresh = input + cacheWrite + output**（缓存读近乎免费不计，**缓存写是实打实处理过的计**）；
命中率 = cacheRead / prompt，无提示词返回 **−1**（"'没数据'和'命中率 0%'是两回事"）。
**命中率只看最近一轮**（累计会被历史稀释）。各家方言归一（OpenAI 反推、Anthropic 单独留 write、DeepSeek 自家字段）。

**⇒ transferable to mcbot:** 照抄公式 + 三条豁免（尤其"从不报缓存"那条，否则本地/自建端点每轮误报）。
落地：(a) 把随世界变的内容从系统提示搬到 per-turn 信封；(b) 给 mcbot 的库存类块做**快照身份缓存**；
(c) 命中率显示最近一轮；(d) 加一个 ≥0.7 判良好的**人可判读阈值**（参考项目唯一写死的效率阈值）。

## 3. 历史 / 上下文经济学

- **触发信号 = 上一次请求的 API 实测 prompt token**；不报用量时退化本地估算：
  **CJK ≈1 token/字、ASCII ≈4 字符/token、每消息 +8**，另加**固定开销 8000**（系统提示+工具表）；
  注释写明"宁可估高提前触发，不可估低撑爆窗口"。
- **触发三条件同时**：`context ≥ 窗口 − 13000` **且** 历史 ≥ **8 条** **且** 连续失败 < **3**。
- **窗口逐模型**来自注册表 JSON，缺省回落 **64000**；值域 200k / 262144 / 400k / 1M / 2M 多档；
  未配置模型默认用 **400k 窗口**的小模型而非最大窗口。
- 压缩**先压缩再发本轮**（压完重入，在压缩后的历史上派发）。
- **近段逐字保留 20000 token**；从最新往回攒，取预算内**最早的**合法切点；
  保留段第一条**只能是 User（首选）或 Assistant（劈轮），永不能是 Tool**——"工具结果必须跟着它的调用走，拆开即 400"；
  预算内无合法切点 → 保留段为空，退化全量总结。另有"历史以最终回复结尾时额外保留那一句"。
- 切点规则被单测钉死（含"保留段里每个工具结果的调用也在保留段里"的孤儿检查）。
- **摘要请求**：独立一句系统提示 + **两步输出**（先草稿标签逐条核对，再正式标签按 7 段结构输出），
  **只保留正式标签**（草稿落盘=白烧 token）；明令不调工具、标签外不输出。
- 边界**先写盘**（追加一条带 preserved 白名单的记录）再换内存 ⇒ 重放压缩后视图，原文留档；
  边界行记账 trigger/droppedMessages/durationMs/preTokens/summaryTokens。
- **失败熔断 3 次**；中断按代数戳丢弃；完成后清空实测用量并把缓存诊断 reset。
- **加载软上限 200 条**，且尾部切片**向前走到最近的 user 消息**（以工具结果开头的切片会被上游拒）；
  启动时扫描**未答复的工具调用**并为每条合成 interrupted 结果（否则下次 400）。
- 双视图同源：LLM 视图（压缩后）与显示视图（物理记录），压缩/清空/换人设只渲染分隔线，不删历史。
- **截断**：派发器日志 200 字符；模型回复日志 120 字符；任务描述进 `<current_task>` **600 字符**；
  评估器 8000 字符/行 400 字符。工具结果各自的 cap：范围方块扫描 **32** 条/半径 ≤**192**、实体扫描 **20** 条、
  配方每查 **4** 变体、脚手架建议 **12**、蓝图层 **24**（再多分桶）、目录回取 **8** 个定义。
- **已知道的世界事实缓存**：工作站记忆**上限 16 条**（最久未动先掉），写穿 JSON，
  每次渲染**对已加载区块自愈核验**（未加载区块按"距离不是不存在的证据"保留），追踪 16 种设施类型。

**⇒ transferable to mcbot:** 补齐五条——**API 用量为触发信号 + 13k 余量 + 20k 逐字近段 + 切点不拆"调用—结果"对 +
失败熔断 3 次 + 边界落盘可重放**。"8k 固定开销"这一手很实用：让"不报用量的后端"也能触发压缩。
"总结只保留正式标签"应写成硬规则。纯 JVM 逻辑，与 `loom-remap`/官方映射无冲突。

## 4. 观测成本

- **自我中心俯视字符网格**：默认半径 **8**（17×17=**289 字符**），可选 **4–16**（半径 16 → 1089）；
  **11 类**移动性字形（含未加载）；**危险格做 8 邻域 1 格膨胀**；下落探测深度 **3**（每列 5 次竖直探测塌成 1 个字形）。
- 输出 = 首行坐标/朝向/方向约定 + 网格 + 2 行图例 + 逐格描路提示；无逐格截断、无行数上限。
- **未加载列直接标"?"**，读取走**只读已加载视图**（非阻塞查询，绝不触发加载/生成）；
  蓝图定价也走同一视图（否则会同步生成蓝图覆盖的每个区块，产生可见卡顿）。
- 设计动机的实测证据：**单次任务曾出现 38 次单格探测**——网格就是为了消掉这些往返。
  已明确**否决**高度图（表达不了悬挑与净空）与稠密体素；多分辨率（近 1 格/远 4–8 格聚合）列出但**暂缓**。
- **全局每 tick 搜索配额（最值得整体搬走）**：**128** 候选检查 + **256** 群系采样 + **256** 区块段扫描
  + 硬墙钟 **4 ms**（≈8% 的 50ms tick），**所有同伴共享**；先到先得；按服务端刻计数复位（`/tick freeze` 不会卡住复位）。
  **刻意没有"加载区块来回答"的许可**——那条路是**被删掉而不是被限流**的（许可在加载前就取走了，代价收不回来）。
- 方块扫描：半径 1..192、结果 ≤**32**、死线 **600 tick**、内部收集 ≤**8192**；
  **一个许可恰好买 1 个 16³ 段**，进行中的列跨 tick 记忆（配额干涸可中途续）；
  未加载列跳过并**计数**（不烧许可）；**精确早停**：保留 want 个最近距离，`worst ≤ 环号×16−15` 即停（与全量走一遍等价）；
  段访问序"中心层先、再上下交替"（"下面有矿，上面多是空气"）；
  结果带**覆盖账本**（已扫/未加载/总列数、是否触死线、是否早停），只有全覆盖才报"半径内总数" ⇒
  **"没找到"永远不会被读成"不存在"**。
- **持久目标索引**：反向「段 → 方块 → 打包坐标」，只存有目标的段；单目标单段**饱和阈值 256**
  （超了只存标记，按需现场解析）；未加载段**每 200 tick** 驱逐；每查询惰性建段、**纯空气段零成本缓存**；
  每查询建段预算由调用方给（挖掘任务传 **48**，注释记录 64 时峰值 3.1ms、48 时最坏 2.5ms）；
  目标集带版本号，旧版本条目查询时重建。变更源接在原版方块变更钩子上，无注册时一次免费闸。
- 最近目标查找：候选上限 **64**、切比雪夫区块环上限 **32**（→512 格半径）、
  **want=1**（注释明确：要 64 个就得证明整个已加载区域，代价完全不同）；一次扫描产出多个候选做**轮换回退**，不必每次重扫。
- 其它 cap：实体扫描半径 1..64 / 20 条；配方每查 4 个、成分最多总结 3 个；
  世界信息仅 5 个字段（最便宜的感知调用）；自身状态**刻意不含背包清单**（历史里沉下去的清单永不过期，会与每轮注入的实时背包打架）。
- **把动态能力文本挂在工具描述里**：本能名册被追加到某个工具的描述上，而描述**每次构请求都会被重读** ⇒
  模型每轮都看到当前名册，且**不破坏系统提示的字节稳定性**——零 token 成本的动态能力暴露法。
- 服务端状态推送：只在变化时推，且**最短间隔 10 tick**；变化判据覆盖物品身份+数量、选中槽、效果集+等级、载具 id，
  **刻意排除耐久/附魔**（挥一下不算变化）；主人离线时刻意不更新镜像，以便回来时仍能检出变化。
- 效果剩余时间**不传真相**：客户端按收到时刻 + 墙钟自己减（20 tick/s）⇒ 派生的倒计时缓存，不必周期重推。
- 位置快照：每次定位请求最多 **16** 个 UUID，一 UUID 一份快照，**陈旧与否由读者按接收时间戳判定**（服务端不设 TTL）；
  "找到了但未加载"被刻意解释为"位置可信、生命值不可信"。线格式里维度字符串长度上限 **256**（解码期边界，不是信任假设）。
- 其它可复用 TTL 形态：调试路径状态 **3000 ms** 后陈旧、读时惰性清扫；调试发布间隔 **5 tick**。

**⇒ transferable to mcbot:** 直接对标：语义网格（1 格=1 方块、半径 8、11 类字形、危险膨胀、未加载标 `?`、
与寻路共用可站立谓词），验收指标用**回合内单格探测次数下降**。
**最有价值的一条**：把"每 tick ≤300 节点"升级为**跨工具的全局每 tick 配额（计数 + 4ms 硬墙钟）**，
把 A* 节点、方块扫描、实体扫描纳入同一预算口。另加"覆盖账本"，让"没找到"不再等于"不存在"。

## 5. 寻路 / 搜索成本

- **线程池**：**max(2, 核数−2)** 固定线程、**无界队列**、守护、**最低优先级**、核心线程 60s 超时回收；
  **所有同伴共用一个池**；每同伴至多一个在飞搜索（重派前先轮询）⇒ 积压被同伴数封住。
  理由："A\* 是纯 CPU 工作，留两核给服务端 tick 与渲染"。
- **未冻结视图回退**：上下文声明"不可安全跨线程"时，搜索**退回提交线程（tick 线程）同步执行**——
  离线程契约的正确性优先于吞吐。tick 线程只做"构造搜索器（构造函数里采样世界边界）+ 提交 + 每 tick 轮询一次"
  （poll 幂等，从不 join）；协作取消 = volatile 标志 + 非中断式 cancel。
- **启发式 7 档 `{1.5, 2, 2.5, 3, 4, 5, 10}`**，**同一单线程循环内顺序推进**（不是 7 个并行搜索），
  每档各自维护最优候选；取用时**按系数从紧到松取第一个离起点超过 5 格的非空档**；七档都不够远 → 判无路；
  系数 ≥3 的档被采用时打"路径质量可能很差"的 debug。
- **anytime 预算切换**：`failing` 初值真 → 先用 failure 预算；某档候选超过 5 格后改为只用 primary 预算。
- 基础单格成本：走 **4.633**、疾跑 **3.564**（权重 **3.563** ≈疾跑乐观值）、跳跃 3.163、下落按表;
  最小改进阈值 **0.01**（防浮点噪声反复重堆）。
- **时间预算是真限制器**：首段 **500ms（有半程）/ 2000ms（毫无结果）**；接续段 **4000 / 5000ms**；
  未地形改造的探路复用首段那对。
- **节点上限 2,000,000 只是失控安全网**，注释三条：(a) 实测挖掘寻路约 **5 万节点/秒**，5 秒预算也才 ~25 万，
  故正常**永不触发**；(b) **不许当 CPU 上限**——大复合目标超 5 万节点才找到路是常事，
  砍在那里就是"误判无路 → 拉黑近处矿 → 舍近求远"；(c) CPU 归线程池与优先级管。命中时返回最优半程，与超时同收尾。
- 主循环**每 64 节点查一次墙钟**（≈0.5ms）；未加载边界触碰上限 **50**；节点表初始 1024/负载 0.75；开集初始 1024。
- 停止原因日志（仅开探针）：`nodeCap | chunkBorder | exhausted | timeout`，带 nodes/maxNodes/failing。
- **部分路径至少离起点 5 格**才采用；路径截尾：长度 ≥**30** 才截、截掉尾 **10%**；
  **预计算下一段**：剩余成本 <**150 tick** 时开始算并**拼接**；已执行路径历史上限 **300**、超限裁开头 **50** 步。
- **快照**：每 tick 重建"同伴周边已加载区块"，**半径 8 chunk**，只收集活区块引用（非阻塞），
  **每 tick 整体重建、之后不再改** ⇒ 无失效追踪、陈旧 ≤1 tick；无同伴的维度宽限 **600 tick** 后释放；
  顺带在主线程抓下"哪些位置有方块实体"，让 worker 做"别拆家"判定不必回主线程活读；
  接受"读活调色板撞上主线程扩容"的罕见竞态 → **退化为 AIR**，执行期重新计价并重规划（"故意用精确性换便宜"）。
- **导航视图不逐格 memo**：只缓存"上一个区块"一个指针；**被实测否决的设计**是逐位置哈希表——
  在一次多秒搜索里膨胀到数百万条并引发 GC 停顿、卡住服务端线程。加载边界外的读一律乐观当 AIR。
- **⚠ 粗层/分层规划器：文档有、代码无。** 设计日志详述了段采样器、六面三态摘要、摘要缓存 TTL 20 tick、
  27 点均质探针、目标侧多源 Dijkstra 距离场、有界不可采纳启发式、保守"封死"判定与 6 个 `COARSE_*` 常量；
  但全仓 grep 这些名字**只命中那份 Markdown**，不存在对应包/类/常量。
  ⇒ 粗层的一切参数（含"远距离启用阈值 48 格"）**只能当设计意图**。既有 recon 报告 §4.3 沿用了文档口径，本报告更正。
  当前代码里真正的远途机制是"接续段预算 + 预计算 + 拼接"。
- **重规划/放弃**：硬保险丝 **200**；连续卡住 **6** 次判被围死；进步阈值 ≈**4.0**（按目标自己的启发式尺度，
  走一格 3.56/上跳 3.16/下落 3.89 ⇒ 约等于"前进一格"，而非到目标中心的欧氏距离）；
  **活目标每 5 tick 重取**（即使目标中心没动也刷新威胁快照）；目标中心移动 >**2 格**即重根。
- **"无路"只在证据完整时才算数**：目标图不完整时最多连续 **40** 次冷图失败才开始拉黑；图完整则立即拉黑 ⇒
  这正是"舍近求远"类持久性错误的解药。单格"打不出射线"连续 **20 tick** 才标不可作业。
- 防活锁收敛守卫：连续孤儿首段 **3** 次、连续"采用了却原地死掉"的无效段 **4** 次即判首段失败。
  恢复阶梯按"每级尝试次数"计，**无全局上限**。搜索结论直方图每 **128** 次派发打一行。
- **执行期每 tick 复核 + 增量重建**：每个 movement 每 tick 按活世界重新计价；进入新 movement 额外**向前复核 5 步**并钉住规划期估计；
  涨价容忍 **10.0**（**只对"规划时该区块尚未加载"的 movement 生效**）；块/放置/撞入集合只重建
  **当前位置 ±10 movement 的窗口**（集合真变了才重建剩余全路径）；偏航 >2 格计时、>**200 tick** 取消、>3 格立即取消；
  "不在任何合法格"宽限 **20 tick**；单 movement 超 **100 tick** 判卡。
- **长活期限按成本推算**：移动 **20 tick/格** + 额外上限 **6000 tick**；挖掘 `max(1200, 数量×600)`（数量钳 1..256）；
  战斗 `min(12000, max(2400, 数量×1500))`（n≤20）；钓鱼**常驻**（给了数量才 `max(2400, 数量×1800)`）；
  建造 `max(1200, 800 + 1.6×估算刻数)`，节奏表生存 **2.0 块/秒**（上限 14400 刻）/自由 **5.0 块/秒**（下限 500 刻）。
  期限单位是**游戏刻**，且**冻结感知**：被抢占一 tick 就把期限推后一 tick（等待规划器在飞时同样推后）⇒ 抢占不被误判成超时。
  "常驻"用哨兵值 `Long.MAX_VALUE/2` 表示。

**⇒ transferable to mcbot:** 最大结构性收益是**搜索移出主线程**（有界池 + 冻结/只读快照 + 时间预算），
撤掉"每 tick ≤300 节点"这个**被点名批评的"拿节点当 CPU 上限"**形态。
配套：(a) **时间预算是真限制器、节点数是安全网**；(b) 7 档系数比单权重更易同时调和深井与走廊；
(c) 部分路径至少 N 格才采用（避免"起步就还你 1 格"的抖动）；(d) **"无路"需证据完整才拉黑**；
(e) 导航视图**只留上一个区块指针**，别做逐格 memo（有实测的 GC 事故）。
⚠ 线程池/快照/预算都不依赖 connection tick，可直接做；但"±8 chunk 快照"要按 mcbot 的票据半径 2 重定。
**不要**按文档实现粗层——代码里不存在。

## 6. 主线程预算

- **身体自己 tick**：假玩家被移出原版客户端区块跟踪（跟踪视图置空、原版调用取消），
  原版移动/落伤/区块垫全部失效 ⇒ **必须手工重实现**：自己的移动通道、
  每 **10 tick** 一次"位置校正 + 区块源跟随"、客户端权威落伤自算。
  ⚠ **mcbot 对应的正是这一条（它没有 connection tick）**。
- **自过期区块票**：半径 **2**（5×5 垫）、票超时 **40 tick**、**每 20 tick 或跨 chunk 续期**；
  身体一停 tick 票自然过期 ⇒ **无显式释放即无泄漏**；多同伴共享一张票；有运行时开关。
  ⚠ 无此垫则每次感知退化为"只有已加载地面"（安全但盲），且自然刷怪不再把身体当玩家存在。
- **调度器挂在 tick 前段**（先于实体更新）使输入当 tick 生效，省掉一 tick 输入延迟；
  后段承载方块扫描推进、区块快照、索引驱逐、调试粒子。
- 每 tick 每同伴顺序：重打区块垫（在服务端 tick 而非实体自身 tick，破"实体 tick 与加载"的鸡生蛋）→
  背包/效果/载具变更监视 → 醒来轮询 → 饥饿轮询 → 主人受伤轮询 → 任务选择。
  区块垫刷新以主人在线为闸（无主人的身体停止占区块）。
- **任务选择是固定 4 级阶梯、无优先级浮点**：本能（注册序，编号 **10/20/30/50**）→ 同步槽 → 当前任务 → 空闲姿态；
  每个槽至多一个候选；"暂停的本能"集合让任务按 id 抑制某个本能，两槽皆空时整体释放。
- **身体只有 2 个槽**：一个同步动作、一个当前任务。落选者被**冻结而不 tick**，
  且每个冻结 tick 把其期限推后一 tick（抢占不计超时）；**结算每 tick 都跑**（因为客户端派发器严格串行，
  不结算就无法推进）。
- **"同批第二件"本地可判**：判据是"记录是否在**本游戏刻**被受理"（`gameTime ≤ startedGameTime`），
  不需要把回合 id 穿到服务端。
- **本能层不花 token**（架构图明写"本能（硬编码，不花 token）"，任何本能可抢占 LLM 任务、完成后归还）。
  逐 tick 评估的本能常数：落体救援（竖直速度 ≤**−0.7** 触发、回收窗 **20 tick**、地面探测深 **40** 格 5 条射线、稳定阈值 **−0.5**；
  **刻意用下落速度而非累计落距**，因为落伤是客户端权威的，在无连接身体上恒为 0）；
  呼吸（头没入且空气 ≤**240 tick**、封顶探测高 **16**、空气空腔 BFS 预算 **400** 格/水平 ≤16、每 **20 tick** 重取目标）；
  自卫（扫描半径 **12.0**、近战危险 **4.0**、平静宽限 **40 tick**、**无战后冷却**——旧冷却曾导致四次重伤）；
  脱困（滚动窗 **40 tick**、位移盘半径 **0.75**、尝试移动占比 **0.8**、爆发 **30 tick**、新航向偏 **+137°**、每第 5 个爆发 tick 跳）。
- **通知去抖动/滞回**：饥饿 ≤**6** 报、≥**14** 才重新武装，一次事件只报一次；
  主人受伤危险线 **6.0 hp**、**14.0 hp** 重新武装、消息档冷却 **100 tick（5s）**、危险档不受冷却但一次下降只报一次。
- **计时器**：每同伴 **8** 个、**1–1200 s**、每 **20 tick** 扫；记主世界刻绝对值（世界不跑表就不走、重启不重新计时）；
  明确只用于"世界不会主动通知你的事"（炉子/庄稼/天亮）——"自己派出去的活用表去盯就是把轮询换了个马甲"。
- 陈旧接受度：寻路区块快照 ≤1 tick；方块实体存在性同 tick；粗层摘要（⚠ 不存在）文档称 20 tick。

**⇒ transferable to mcbot:** (a) **"本能层不花 token" + 可抢占可归还**——把自动进食/脱困/反杀移出 LLM 循环，
直接省掉这些高频场景的 token 与思考延迟；(b) **两段时间纪律**（客户端宽松墙钟兜底 + 服务端紧的、冻结感知的游戏刻期限）。
⚠ 告警：手工重实现身体 tick + 屏蔽区块跟踪 + 每 10 tick 位置校正，是"假玩家无连接"的必然代价——
mcbot 需逐项确认（`ARCHITECTURE.md` 只记了"挖掘手工计时引擎"）。mcbot 票据已是自过期，可补"多同伴共享一张票"。

## 7. 身体 / 动作经济学

**三路受理（单一真源）**：(1) **不占身体**（查询/UI/登记）→ 不进任务系统，当场回结果；
(2) **占身体 + 有界短** → 同步派发，回合挂着等；(3) **占身体 + 无界** → 异步派发，**受理即回执**，身体后台跑、大脑当场自由。
**"常驻"不是第四条路**：同一异步入口，**给不给数量**决定会不会返终态。
- **一具身体一件活**：槽里有活时新的异步派发与同步动作**一律拒绝**并报出当前任务号——
  理由："排队不可取：串行的工具派发器会被长活整个卡死"。
- **替换式受理是常态**：派新活直接顶掉旧活，不要求先叫停；**唯一拒绝** = 槽里那件是**同一批工具调用里刚受理的**
  （"说明模型一回合连派两件，该让它拿到第一件的结果再决定"）。**被替换的活一定会被结算**（标 REPLACED→CANCELLED 并结算），
  否则对话里会留下永远没有结果的工具调用（下次 400）。
- **拒绝话术三分支**：常驻说"它永远不会发完成事件，直接派新活就是停它的方式"；外接调用说"查状态"；内脑说有界活"别轮询，完成会来"。
- **避免轮询**：收尾走事件（完成/失败/超时/被叫停），按队列三态路由自动落进"立刻开轮"档；
  **超时事件携带进度**（由任务自己给，不是自动注入），重派同一调用可续做；
  **目标重算在任务层、进度携带只在寻路层**——重派 = 从当前世界状态重新求解（背包里已有的收获天然就是进度），
  已算路径由寻路层自己缓存；任务层**永不做挂起/恢复簿记**，因此天然无陈旧状态。
  活进度经**服务端推的** `<current_task>`（已过秒数/是否常驻/≤600 字符描述）到达模型；客户端只照抄不推断。
- 完成路由决策表：异步+内脑 → 完成事件（done/timeout/stopped/failed）；异步+外接脑 → **不发事件**（由驱动方查状态）；
  同步 → 只发主人的结果包（主人离线则丢弃，重登时按"未答复调用"修复）；死亡 → 仍为异步活发 interrupted 事件，
  以不破坏"别轮询"的回执契约。除"被叫停"外所有任务状态都算急件。
- **收件箱**：主人的话与世界事件**共用一条队列**，上限 **200**，满了**丢最老并记账**，排空时如实补一句
  "你看到的可能不是全部"；成熟度只有两条：**有急件→熟**，否则看**条数**（档位 1–10，缺省 3）或**年龄**
  （等待上限 `60s×档²/3`：1 档≈20s、3 档=3 分钟、10 档≈33 分钟）；**躺超 10 分钟的事件标注年龄**；
  排空**只取开头连续一段**（遇控制条目即停，不插队）；倒箱拼成**一条**用户消息（状态快照 → `<events>` → 主人的话压轴），
  多条缓冲的主人话合并进同一条以避免连续两条 user 消息。
- **"禁止轮询"只有提示词级强制，无运行时冷却**（⚠ 已知缺口，不是优点）。
- 网络包体积硬上限：工具调用 id **128**、工具名 **128**、参数 JSON **16 KiB**、结果 JSON **16 KiB**。
- 主人打断：**代数戳自增**，在飞响应落地即弃；每个未决工具调用合成 cancelled 结果保住协议；
  排队中的指令类条目清掉、事实类保留。
- 其它节流：手动放置意图释放宽限 **600 tick**（对串行派发器的空闲间隙去抖）；
  当前任务镜像推送最短 **20 tick** 且只在 id 或人话描述变化时推（⇒ 最多 1 包/秒）。

**⇒ transferable to mcbot:** 整体搬走：三路受理、"常驻不是第四条路"、**"同批第二件才拒绝"**（本地可判）、
**被替换的活必须结算**、收尾走事件顶替最后一次往返、注入任务镜像时**明确"直接派新活顶掉旧活"**、
任务层不做挂起/恢复簿记、收件箱的档位化成熟度 + 年龄标注 + 丢弃记账 + 倒箱拼一条消息。
另建议给 mcbot 的桥加同款**包体积硬上限**（现在只有一个整体 body ≤64KB）。

## 8. 度量与仪表

- **逐调用一行 INFO**：耗时 ms、SSE 块数、token（in/out/total）、结束原因、工具名列表、正文片段（≤120 字符）——
  全仓最便宜的"每轮延迟 + token + 块数"仪表。每次调用有短序号请求 id 贯穿"发送/响应/每块"的日志行（重试带 r1/r2 后缀）。
  请求开头 debug 行给出 `msgs` / `tools` 数量 / **`system_prompt_chars`**（缓存前缀体量的直接观测）。
- 传输层：发送 DEBUG 带字节数；2xx DEBUG 带 ms+块数；失败 WARN 带 ms+块数；空闲看门狗杀流 WARN；
  重试 WARN 带算出的延迟与"第 n/2 次"；**仅在不可重试的拒绝上**才 dump 自己的请求形状（消息数/工具数/body 字节/完整工具定义）。
- **逐回合**：`turn N: convo=X msgs, tools=Y`；`runtime_state` 全文 debug（靠它抓到过"完成事件与任务镜像在同一条请求里打架"）；
  背包块进请求时打**字符数 + 快照年龄 ms**，且**只在快照身份变化时打** ⇒ 该行读的是"背包这段时间没变过"，
  **该行不出现才是链路断了**；工具派发/结果各一行 INFO 带排队深度。
- **逐会话持久化**：四元累计 + 新处理总量，每回合一写（文件极小）；命中率与缓存诊断**不落盘**；
  `/usage` 面板把最近一轮命中率上色（**≥0.7 判良好，否则告警**）并单列一行"缓存重付了 N token，M 次" ⇒
  **这是把诊断指标变为人可判读信号的那一步**。压缩边界行携带 preTokens/summaryTokens/droppedMessages/durationMs 作为跨会话成本历史。
- **寻路探针（默认关，一开即 5 秒一窗口 INFO）**：窗口 **5000 ms**；含 navTicks（含 /s）、
  每阶段的 次数/总 ms/均 µs/峰 ms（插桩相位 = 目标编译 + 核心 tick）、后台搜索 次数/总/峰、
  线程池 线程/活跃/峰值/完成增量、GC 次数与停顿 ms（**占窗口百分比**）、
  服务端 tick 间隔 `gapMax` + `over60` + `over100` 计数。
  **"总 CPU 时间可以远超窗口墙钟"写进注释**（后台搜索并行跑多核），否则读日志的人会当测量错误。
  **健康基准写在代码里：tick 间隔 ~50ms 为顺、>60ms 计数、>100ms 抓栈**；间隔 ≥2000ms 视为任务空档不计。
  **卡顿抓栈**：后台线程每 **25 ms** 抓一次服务端主线程栈进 **64 槽环形缓冲**（≈1.6s 现场窗口），
  压缩到 ≤10 帧，tick 间隔超 100ms 就打出（最多 3 个不同栈）——**覆盖所有计时相位之外的盲区**（光照/区块 I/O/别的 mod）。
  **没有 nodes/s 计数器**；节点数字只在开探针时的每次搜索收尾行。
- **回归门**：官方 CI **只回答"能不能编译 + 纯 JVM 测试"**，**没有任何性能阈值门**；
  性能靠探针人工判读 + 设计日志逐条记账。⇒ 性能回归门在本仓**没有自动化形式**（可借的是指标本身 + 健康基准）。
  真正被断言钉住的是**正确性**：缓存诊断（含豁免规则）、压缩切点（含孤儿工具结果）、用量归一、队列成熟度/丢弃记账、
  目标轮数/正文截断、期限不回退/不溢出、计时器到期与上限等数值单测。
- **度量缺口**（别照抄）：无每任务耗时直方图；除探针窗口外无队列深度/池饱和度计数；
  除 token 台账外无持久化的轮次或延迟聚合；按明确决策**任何地方都不放价格字段**。

**⇒ transferable to mcbot:** mcbot 验收纪律是"证据（时间戳+日志判读）进 STATUS"，正缺一份**可复跑的性能哨兵**。照搬三件：
(a) **`gapMax/over60/over100` 三计数 + 超 100ms 抓主线程栈的环形缓冲**——"服务端卡还是客户端卡"的决定性信号，实现极便宜；
(b) **5 秒窗口分阶段 次数/总/均/峰**汇总行；(c) **`system_prompt_chars` + 缓存漏计**双指标一起进日志
（前者定位谁动了前缀，后者量化代价）。把 mcbot 的"每 tick ≤300 节点"直接进这份哨兵作被监控量；
其无头 `SelfTest` 适合作为这些计数的自动断言载体（比参考项目"只测正确性"更进一步）。

## 三条最贵的建议

1. **把 mcbot 的 A\* 移出主线程**（有界池 + 冻结/只读快照 + 时间预算），撤掉"每 tick ≤300 节点"——那正是参考项目**点名批评的"拿节点当 CPU 上限"**形态。单任务墙钟最大的一笔。
2. **加"缓存浪费诊断 + `system_prompt_chars`"双指标**，并把所有随世界变的东西赶出系统提示（机制便宜、收益持续，能防住"有人往系统提示塞了个会变的字段"这类静默退化）。
3. **建一份可复跑的主线程性能哨兵**（gapMax/over60/over100 + 超阈值抓栈 + 5 秒分阶段汇总）接进 `SelfTest`，让"没卡崩"从人工判读变成自动断言。

## 依赖告警（mcbot 无 connection tick，以下机制不能照搬形态）

| 参考项目的机制 | 它依赖什么 | mcbot 的对策 |
|---|---|---|
| 15 分钟工具兜底 | **客户端 tick** 驱动检查 | mcbot 的 `AgentRunner.tick()` 在客户端主线程做超时巡检 ⇒ 形态可用，但要确认兜底时长与"桥断线"叠加后的行为 |
| 队列"条数/时长"成熟度自动排空 | 同一条客户端 tick | 急件在 push 时直接叫醒不受影响；**非急件的按龄排空在 mcbot 需要自己的 tick 或定时器** |
| 计时器到期 / 饥饿 / 受伤 / 醒来 / 复活 / 区块垫刷新 | **服务端 tick 循环** | mcbot 已有 `CompanionScheduler`（`END_SERVER_TICK`）⇒ 可直接承载，且身体在服务端**比参考项目更直接** |
| 背包/效果/载具状态进入请求 | **服务端推快照** | mcbot 已有状态推送包路径 ⇒ 可做"身份缓存 + 变更才推" |
| 身体自己的移动通道 / 每 10 tick 位置校正 / 落伤自算 | 手工补偿无连接的身体 | **mcbot 必须逐项确认这三件**（`ARCHITECTURE.md` 只记了"挖掘手工计时引擎"） |
| 粗层/分层规划器（48 格阈值、距离场、封死判定） | **代码里不存在**（只有设计文档） | 不要按文档实现；先用"接续段预算 + 预计算 + 拼接"拿大部分收益 |
| 每 tick ±8 chunk 快照 | 与它的票据半径耦合 | mcbot 票据半径是 2 ⇒ 快照半径要重定，不要照抄 8 |

**两处"看起来能抄、实际要当心"**：
- **"禁止轮询"只有提示词/措辞级强制，无运行时冷却**：参考项目自己也没防住反复查状态的模型 ⇒
  mcbot 若要做，得自己加每任务查询冷却（本轮勘察未发现参考项目有此机制）。
- **并发工具调用被请求为真，但身体严格串行**：批量是"请求侧"的收益，不要在身体上并发执行（一具身体一件活是硬约束）。
