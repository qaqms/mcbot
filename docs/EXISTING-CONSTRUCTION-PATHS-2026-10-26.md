# 施工优先利用已有通路

本轮针对上层施工偏爱直线拆改/垫柱的问题。最终构建、候选指纹与真实测试边界见STATUS顶部。
参考为开发环境中的只读副本；仅分析机制，不复制或翻译其代码、注释、文档及资源。

## 证据与根因

本轮启动时实例安装包为上一轮search-stall候选；新的latest.log主要为地下采掘，
未把该段当作新版本上层施工失败。建筑证据沿用build/path-stall-evidence-20261026.log：
00:33:48至00:34:07的339至347路线反复新增支撑，上层367/368/373/376曾持续空搜。
历史证据不能证明每一处支撑都多余，也不能当作上一轮估价/停滞修复已在现场失败。

代码可以独立复现路线选择问题：

- 贪心阶段按剩余距离和工作站位引导排序，累计行走/挖放费用不进入主排序键。
  编辑数仅用于相同优先级时的比较，不能抵消指向直线路线的估价优势。
- 得到可行解后，分段模式只做有限改善；它适合快速交付地下可挖阶梯，
  但不能保证在施工手距平台上发现先远离目标、再绕到现有入口的路线。
- 丰富材料时放一格约等于走一步，挖掘费用也不表达恢复成品/回收支撑的全部后续劳动。
  直接提高这些价格仍不能解决贪心阶段未计累计价格的问题。
- 累计TerrainEdits意味着同一坐标的不同编辑历史不能直接合并。为加速而删掉历史会
  破坏脚手架、净空和待补义务的真实区别，不能用来解决本次问题。

旧码新增纯算法场景中三项失败：有入口却拆墙、有侧通道却搭桥、组合目标挑中需拆改的近格。
原版形状/射线的上层场景中，身体位于完整楼板下，旁边已有向外绕行的三级台阶。
旧码展开42节点并计划拆楼板1格、垫柱2格。该场景另明确验证上层有真实可点击的放置接触，
不是只有手距、没有实际工作面的假目标。
证据为build/existing-work-before-20261026.xml及existing-work-scene-before-20261026.xml；
scene-before第一版夹具把目标放在无可点击顶面的浮空锚点上，已修正为侧面锚点，
不能把第一版夹具的无路结果当成生产故障。

## 参考相关机制

| 参考链路 | 实际机制 | 本轮处理 |
| --- | --- | --- |
| BuildCompanionTask / BuildOrder / Arrival / Goals | 低层优先，手边工作先做，组合工作目标，移动结束再核现场 | 保持已有同层组合导航与严格PlacementWork，不退回精确目标中心或凭距离施工 |
| AStar的两遍搜索与停止判据 | 首遍可快速取解，后遍比较累计动作费及有效下界；昂贵首解不只因已找到就结束 | 学习可行性与路线偏好分开；本地增加有界已有通路检查，不照搬其最优界结论 |
| CostModel / ActionCosts / RouteSpec | 行走、挖掘、放置、许可与危险价格分工，能做不等于值得做 | 保持原准入与物理费用，先在不新增编辑的子图中选路，不靠任意放大价格代替准入 |
| Estimate / Vertical / Favoring | 将水平、升降及必要工作分开；旧路折扣也影响有效估价底价 | 新检查累计行走费用，保留已有跳跃/下落及旧路折扣，禁止只凭目标直线距离排序 |
| Moves / Driver / TripMemory | 搜索和执行共步型，实际失败记有向步骤，只有新学习才继续无路线搜索 | 保持原PathTransition及现场复核、停滞回模型；未声称完成跨段学习/受阻步骤迁移 |
| NavigationContinuation / EditedView相关链路 | 段尾带预测落点及未落地改动，采用前重验 | 工地接续同样启用已有通路偏好，保留本体完整累计地形与材料预留 |

参考的完整身体运动、编辑历史身份及估价证明与本体不同。它没有本轮相同的
“最多256节点先查已有通路”规则；这是适应本体严格工作目标与原搜索结构的独立实现。
参考部分建筑直接写最终状态，本体仍须真实点击、原版放置、材料消费及全图验收。

## 本地契约

DigAStar在严格放置目标，或PathTask明确启用施工通路偏好时，先尝试不新增编辑的路线：

- 在advance原时间切片内启动；不先扫描整份工作位反向场。按已走费用加剩余距离排序，
  不因暂时远离工作目标而在主排序中无限排后。
- 仅本阶段给PathTransition零新增挖放余量；原世界、支撑、未知、危险、范围、
  当前累计TerrainEdits和工作视线判据完全相同。到达费用须为零，不能把还需清障的工作位冒充无编辑。
- 最多使用本次节点额度的八分之一，且不超过256节点；过小额度或完全不能挖放时不增加此阶段。
  这是偏好检查的计算规模，不是整趟搜索/路线/任务时限，不保证发现任意长的绕行。
- 找到路线即提交；无结果或子图走完则进入原贪心/加权编辑搜索。前段探测的节点、
  CPU、记录和可逆半程候选沿同一账户，不能重置显式额度。偏好阶段的零余量拒绝不污染
  原搜索的DIG_LIMIT/PLACE_LIMIT等诊断，也不证明原权限下无路。
- PathTask的工地普通移动、清障工作接近和行进中接续同样启用；普通地下采掘不默认启用，
  避免把短距离挖矿变成额外的大范围步行搜索。全程保持原取消、停滞窗口和原生动作入口。
- departure_blocked按最终搜索图是否只有起点区分，不能因偏好探测多花了一次起点记录而漏报封闭起点；
  偏好阶段失败本身不能触发该标记。

日志增加existing_path与existing_expanded；活动观察和失败诊断提供
existing_path_selected及existing_path_expanded。它们只描述规划选择，不是实际挖放或施工完成证明。

## 验收与边界

ExistingWorkPathTest验证入口绕墙、绕缺口、组合成员、必要挖掘/搭桥回退、
续段既有支撑不重复扣料、显式节点与过期CPU/切片，以及工地位置导航的显式启用和封闭起点。
HouseWorkSearchTest的上层场景修正后走既有台阶，150节点、零新增挖放，
没有4050次工作位预扫描；真实形状/射线参与，权限、工具价格及状态预测仍为受控替身。
原需要登高的局部存档屋面场景继续允许2格支撑，106变为169节点，额外63节点为已有通路检查，
不虚报成所有路线都更快。

没有实现参考全部运动模式、自动开关门、全量编辑后台化或完整跨段学习；
未证明任意已有绕路都能在偏好窗口内找到，也不承诺全局最短或最少编辑。
未安装实例、启动游戏/宿主服务/真实模型；真实施工路径、动作流畅和模型调整仍待新包复测。
