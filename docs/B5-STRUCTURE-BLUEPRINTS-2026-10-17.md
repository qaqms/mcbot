# B5：首个有界蓝图格式

本卡首轮接入原版gzip结构.nbt，续卡增加完整的原版普通双格门。
普通单格仍沿B1状态要求；门的两半也走同目标、材料、原动作、记录和最终核验入口。
没有声称全部格式、多格、装饰、组件、红石或模组工程已经实现。
这些扩展须在本格式独立验收后按实际需求另立范围，不通过放宽材料/原版动作来完成。
最新测试、候选、提交及未测边界以STATUS/Git为准。

## 参考机制核对

只读学习开发环境中的参考副本（路径不入仓），未运行参考构建或测试，
没有复制或翻译代码、注释、文档、提示词或素材。

| 参考源码后缀 | 完整链与本体取舍 |
| --- | --- |
| blueprint/BlueprintStore、BlueprintFormats | 文件发现、压缩NBT、尺寸/调色板、格集、状态/旋转、稀疏空气和格式转换；本体仅一种原版结构格式，固定目录、严格类型/边界，不采用无限堆分配或默默丢坏格 |
| build/BlueprintSafety、BuildStates、Layout | 载荷允许范围、组件材料一致、原点/实体坐标、复杂对象依赖；本体首轮不导入任何方块实体载荷/实体/组件，缺口明确阻止整个设计导入 |
| tools/BuildOps、tools/work/BuildApi、modules/build.lua | 只读文件事实与材料、同目标差异、有限施工和最终重查；本体导入到B4设计，再用相同实例引用/材料/原挖放/Lua，不另建蓝图执行器 |
| task/build/BuildCompanionTask、BuildTaskRecord、BuildOutstanding | 实际消费/逐格记录、二次查询已有满足、未知/不支持/没留住及取消；复用B1-B4，不直接写状态、不把跳过当满足 |
| gametest/BuildGameTests 的文件句柄/料单/损坏文件/多格次半/装饰内容/二次无消费 | 核对坏下标、体积炸弹、次半覆盖、内容免费生成/恢复错位等风险，自编离线回归，不把参考GameTest当已运行 |

参考的litematic/schem转换有自己的稀疏空气、区域、位流和载荷语义，不能只改扩展名就接入。
这些格式本卡明确不支持；原版结构里的显式空气沿B1表示清空要求，未列格不触碰。
参考复杂对象的“组件计价与实际落位用同一份真实物品”是后续必要机制，
首轮不会仅保留装饰外观而漏掉材料、次半占位、来源与最终验收。

## 工具和数据流

新增build_blueprint，当前29工具（20服务端、9本地）：

- operation=list：只读当前世界mcbot/blueprints目录，名称不带.nbt，offset按16项分页。
  不存在则报告目录不可用/空表，不为只读查询创建目录。仅列合法常规.nbt文件，
  其他文件/目录/符号链接计ignored_files；目录超过扫描帽拒绝，不无限遍历。
- operation=inspect，name：解析一次，返回source_revision、size/cells/palette_entries、
  压缩/解压字节和invalid_cells、invalid_palette_entries、unsupported_cells、payload_cells、
  entity_count、最多8项坐标诊断及诊断省略标志。载荷内容不出站。
- operation=import，name/source_revision/design_id：重新读同一文件，确认完整源哈希一致，
  且所有格/状态/载荷条件支持后才创建B4设计。须原数据修改许可，重复design_id不覆盖。
  inspect只读成功且importable=false仍不能导入，失败不产生删减版设计。

普通模型调用、Lua调用和长期阶段走同工具注册、Schema、只读/控制门及原子调用账。
导入不实例化、不动世界、不自动找料，不登记或完成外层目标。
后续用build_record instance_create选择锚点/朝向，返回target引用直接交原
build_diff/build_site/build_nearby或mc.build，仍须真实通道、范围、库存、原动作许可和终态。
取消后迟到的inspect结果不会触发import；没有自动重试、动作重播或预算补充。

## 格式边界

只认gzip压缩的原版结构根：

- size：3个精确IntTag组成的列表，各轴1-33，体积最多4096；
- palette：1-64个{Name,Properties?}，Properties最多8个字符串键/值；
  全部进原B1注册表/状态校验，包括未引用项。未知方块或非法属性不归一成空气；
- blocks：1-128个{pos,state,nbt?}，pos为尺寸内三整数相对格，state为精确IntTag下标；
  重复格、类型错、坐标越界直接拒绝；非法下标/状态保留invalid计数，不导入部分目标；
- entities：只能为空；非空保留实际entity_count并阻止导入；
- DataVersion可为IntTag，author可为最多128字符StringTag；只作惯常格式元数据，
  不导入作者文字，不执行数据升级或按新旧版本猜状态映射。

不支持多调色板palettes、根额外字段、其他压缩或文本格式。
nbt即使是空复合标签也算payload_cells；所有方块实体内容、战利品、命令、点击文字、
物品组件和实体一律不带入。普通炉等已有单格无载荷方块仍按B1真实材料支持范围判断，
床、流体、双层半砖多动作及未支持类别明确计unsupported，不能跳格冒充完成。
门仅支持下面明确的完整双格契约，不能只写下半、自动扩图或忽略上半。
明确给出的作者属性不忽略，旋转仍由原BuildTarget/原版BlockState完成。
即使导入成功，当前身体姿态/支撑无法原生摆出的状态仍须在diff/施工中报告，不能强写。

materials仅表示该设计有界已知需求，最多16种并报告省略，不是当前库存/剩余料单；
材料齐备及当前差异按实例build_diff独立完整分页核对。inspect/import的goal_satisfied始终false。

## 文件和解析预算

只从当前世界固定目录读合法1-48位小写字母/数字/下划线/连字符名称，首位字母/数字，
不接受扩展名、盘符、斜杠、目录跳转或链接；不跟随mcbot目录、blueprints目录或文件符号链接。
读前/后核文件身份、大小与修改时间，按实际读到的压缩字节计算SHA256源修订。
不把文件名当任意路径，不在服务器范围外搜文件。

目录扫描最多128项；压缩64KiB、解压128KiB、NBT计费堆256KiB、嵌套16层，
整体200ms协作时间帽。原生NbtIo/DataInput配显式NbtAccounter；数组声明在分配前受计费限制，
流读取/跳过和各解析阶段检查字节/时间，尾随NBT、截断gzip或坏CRC拒绝。
200ms不能强制中断一次操作系统文件读取或原生解压调用，不宣称严格主线程实时上界。
不扩大原B1格数、范围、材料、原Lua/模型/探索/施工/导航预算或许可。

## 双格门续卡

本轮再次核对参考BuildStates、BuildCellRules、BuildSurvey、BuildCompanionTask、
BuildTaskRecord、Changes、Built、PlacedBlocks、modules/build.lua和双格次半/取消/改图测试。
学习的是同一对象的占位、一次材料、真实变化与后续核对相连，未复制或翻译参考内容。
参考通过过滤次半避免重复放置，部分施工直接写状态。本体采用显式两格目标和下半唯一动作，
保留两半独立验收，仍只调用原版BlockItem.place，不过滤次半或直写状态。

1. 支持命名空间minecraft且精确DoorBlock类的门；不扩大到门子类、床、高植物、流体或任意多格模组。
   两半须相邻上下、同种门，各自明确half/facing/hinge；属性集合及除half外的明确要求须一致。
   open/powered可不指定；明确指定则原样核验，不归一、不放宽或自动开关门。
   缺半、冲突、另半被指定air/其他方块仍保留unsupported缺口；工地不接受这种目标。
   两格均计入原128格、相对±32、实例不重叠及实际范围限制，不自动补出越界格。
2. BuildObjects是同源配对/原生占位规则。BuildSurvey全目标只采样原128格后复用观察，
   料单按下半一件、上半零件；任一半未满足仍有一件剩余需求，未知另记未决，不把半扇门报价为零。
   当前页只分配下半，空上半为paired_pending；即使两半跨页，也不会单独放上半。
   两半已有满足时零动作零消费；现场只有半扇时须有活来源的显式清理，不覆盖另一半“修补”。
3. 单放、只读预检、工作导航与近身施工共用原BlockPlacement。
   1.21.11字节码确认DoubleHighBlockItem.placeBlock会先处理上格，DoorBlock.setPlacedBy再生成上半。
   因此两格须空气，上格连可替换草也不覆盖；两格各核世界/加载/交互、实例/范围/通道保护、
   自身及实体碰撞，执行前再核。原版负责接触、朝向、合页、支撑和真实扣料。
   假想站位仍读实际原版上下文，不支持未落地邻域编辑、临时双格工程或强制摆出目标朝向。
4. 一次原生动作计原工地一次改动尝试、Lua一次已声明动作预算，最多产生两条真实变化事件。
   前置预留两格记录容量，原256事件/128来源格/64工作格及每区块64见证帽均不扩大。
   记录逐格前后确切状态，主格记真实消费，次格消费为0；一件真实消费只可认领原空气且
   满足本格目标的原生生成格，已有/替换/错误格不认领。原子保存两格记录，异常与取消保留实际部分效果。
   两半可以已满足而动作因异常或不正常消费失败；失败结果仍失败，最终现场条件由独立观察报告。
5. 原BlockMining按门的真实两格占位检查连带影响，并在原生破坏finally记录两格实际变化。
   返回native_effects，不把连带移除当成入包；掉落归因沿原F2，最终材料仍查背包。
   工地拆改必须同实例、同修订、两格活来源/准确状态/原区块、新鲜材料、采收、依赖与通道检查；
   已完整满足的门不拆，缺半时可显式清掉剩余有来源格，外部替换/状态矛盾/未知则整个对象拒绝。
   改图退役的两个来源格成为同目标两格air，仍走原挖掘许可，不自动拆或返还材料。
   两格保存重进后均无活见证，不恢复拆除权；明确新调用可按实际空气继续，取消不自动恢复。

这仅完成B5的一类复杂对象续卡，整张B5仍未关账。床及装饰/组件需要各自完整材料、
占位、动作、来源、冲突和最终核验，不能复用“次半零件”就宣称已支持。
