# 游戏内 G 面板（2026-10-13）

本轮按维护者认可的 HTML 原型落实原生界面。实现与离线证据见 `../STATUS.md`
「R3 G面板重设计」及「R3窗口化修正」。
维护者游戏内体验反馈原版全屏遮挡，现已改为居中窗口；修正版游戏内效果尚待确认。
参考项目仅用于理解机制，没有复制其代码、文字或资产。

## 页面与任务交互

- 对话、同伴、设置三页。面板居中，常规宽度约屏幕80%、高度约83%，
  最大760×460 GUI像素；极小窗口至少留8像素边距，并保留可滚动的表单空间。
  历史页和确认框同样窗口化，最大440×320 GUI像素。
  四周直接显示游戏，不绘制全屏底色或使用原版菜单模糊。
  宽面板左侧导航，小面板顶部导航；默认浅色，可切深色，右上角可关闭。
- 对话区区分主人指令、同伴回复、问题与提示；连续工具过程默认折叠，可展开查看和复制回复。
  固定多行输入框：Enter发送，Shift+Enter换行；切页、滚动和控件重建保留草稿。
- 显示真实任务状态、AgentLoop步数、挂起工具及上下文用量；受理/进度不冒充完成或完成率。
  有活动/排队任务时发送新指令需确认停止并改派；停止入口取消全部任务。
- 会话历史按任务回看，历史视图只读，可返回当前对话。显示档案由PanelHistory独立维护，
  当前世界会话内最多20个任务、2000条记录；退出世界或重启后不保留。
  模型整理、清空上下文和连接重建不会删除当前会话的显示档案。
- HUD仅在任务进行/待答时显示，任何界面打开或hideGui时隐藏，可在通用设置关闭。

## 反问与授权

面板读取原问题ID、task_id、全文和120秒剩余时间，回答复用现有一次性答复入口。
答复草稿绑定原问题ID；问题过期、取消或已消费后，旧答复不能变成新任务或答到新问题。
聊天回答入口仍可使用。

涉及权限时展示完整服务端授权清单，不使用模型改写文本替代。
确认框需滚动到末尾且原问题仍有效，才能批准；按End/PageDown也可阅读。
批准继续走原服务端授权回执，面板不改变只读/owner/一次性授权规则。

## 同伴信息

通过现有白名单只读 `status(details=true)` 取得真实身体快照，不调用模型。
显示生命、饱食度、位置/维度、游戏刻、36格存储与快捷栏、选中槽、
物品数量/耐久及装备。缺少完整背包数据时明确提示明细不可用。
刷新按runner和身体代际隔离迟到结果，A→B→A也不接受旧快照。

皮肤和物品图标使用原生资源。物品图标按注册ID展示基础外观，
不假设快照包含未回传的自定义名称、附魔或组件；点槽不会搬运物品或切换主手。
召唤、刷新及带确认的遣散使用原生命周期入口。

## 模型与配置

设置分模型、上下文、通用三个子页。
模型页保留API地址、模型名、掩码密钥及多行人设。
`MCBOT_BASE_URL`、`MCBOT_MODEL`、`MCBOT_API_KEY` 覆盖字段显示来源并锁定编辑。
连接检查仅用户主动点击时调用独立测试模型，不派发游戏工具，不自动保存。

保存采用差分处理：地址/模型/密钥变更需确认取消任务及待答问题、重置模型上下文；
只改人设或显示/上下文偏好不重建大脑、不取消任务，人设在下条指令边界生效。
执行权限模式变更会取消当前及排队任务、撤销待确认问题，保留大脑和显示历史；
重新提交任务后使用新模式，旧问题/授权/迟到动作不能接续新任务。
写盘失败显示失败，不应用新运行配置。通用页含主题、工具折叠、HUD、桥状态与令牌复制。
桥契约和鉴权边界不变，令牌不在面板正文展示。

### 自主执行

G面板 → 设置 → 通用 → 执行权限 → “自主执行（免确认）”，点击保存设置。
默认关闭，旧配置保持逐次确认；开启后路线挖放及中立/命名目标攻击不再请求逐次批准。
配置字段为autonomous_actions布尔值，保存在当前客户端实例的mcbot/client.json，
对该实例之后提交的任务生效，包括桥接投令；不是世界内的永久规则表或模型可写参数。
本卡不替维护者改玩家配置、不自动开启。

服务端从主人客户端的task_begin取得模式，模型工具参数不能升级权限。
明确只读任务优先：即便偏好开启，自主标记也不会授予只读任务动作能力。
新任务先读服务端实际permission_mode；自主模式未被服务端确认时，
在模型请求前以MODE_UNAVAILABLE停止，提示同步更新客户端/服务端或恢复确认模式。
普通信息澄清问题仍可询问；改派、遣散、清空上下文等界面确认保持原有含义。
身体归属/任务身份、资源锁、取消、原版动作/距离/工具/世界规则与现有保护继续有效。
自主执行不是自动清理埋藏遮挡、路径修复或任意长期任务完成保证。

## 上下文设置

新增字段仍保存在客户端 `mcbot/client.json`，旧配置缺字段时使用默认值：

| 字段 | 默认 | 含义 |
|---|---|---|
| context_window | 64000 | 手工填写的模型窗口，进入完整请求/摘要输入预算守卫，不自动探测模型能力 |
| compact_threshold | 6000 | 自动整理的历史软水位，固定system/工具/本轮观测不计入；完整请求另受窗口约束 |
| recent_budget | 1500 | 近期原文保留预算，沿用原默认值 |
| auto_compact | true | 工具完整结算后的请求边界及正常链尾按阈值整理 |
| fold_tools | true | 默认折叠显示工具过程 |
| dark | false | 深色主题 |
| show_hud | true | 任务/等答HUD |
| autonomous_actions | false | 主人选择的自主执行；新任务免动作批准，模式变更停止旧任务，只读优先 |

窗口范围4096至2000000，阈值至少2048且小于窗口，近期预算至少256且小于阈值。
无效预算整组回退默认偏好，原 `accept_mode` 保留。40步、3/5重复护栏、
90秒普通工具等待、120秒反问期限仍为原固定规则。

用量区分最近请求的服务端报告与本地估算，摘要来自实际Conversation。
自动整理发生在工具完整结算后的任务内请求边界及正常链尾；整理后重新观测身体，
只有足量旧段才显示整理提示，摘要必须带来净节省，否则保留原文；不因固定工具表反复整理。
原指令及已登记目标数量独立保留。完整请求/摘要输入均受配置窗口约束，
仍超预算以CONTEXT_LIMIT停下。手动整理仅空闲时开始，并与新任务串行。
失败保留原上下文。清空需确认，取消任务、问题和在途摘要，
模型从空白上下文开始，显示档案保留。前缀重置新增 `context-clear` 原因。
