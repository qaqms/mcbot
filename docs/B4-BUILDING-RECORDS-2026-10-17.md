# B4：可复用设计与实例事实

本卡为原建筑能力增加世界内的数据记录。短任务、长期阶段和身体施工仍共用
BuildTarget/BuildSurvey、BuildSite、BlockPlacement/BlockMining、原scheduler和Lua组合；
不增加材料依赖规划器、成品链或自动恢复器。验证/候选/提交以STATUS与Git为准。

## 参考完整链

只读核对开发环境中的参考副本（路径不入仓），未复制或翻译代码、注释、文档或素材：

| 参考源码后缀 | 学习内容与本体处理 |
| --- | --- |
| build/Design、Canvas、Placement | 数据与执行分开、固定原点与原生旋转；本体沿B1的128格/相对±32/明确作者属性，不扩参考16384格帽 |
| tools/BuildOps、tools/work/BuildApi、modules/build.lua | 同设计多落点、差异与施工共用入口；本体实例引用交原diff/site/nearby及mc.build，不另建动作接口 |
| build/Built、Changes、BuildValidity | 实际逐格记录、旧图不再需要的自建格与外部变更；本体保存确切状态和实时逐格见证，不用仅方块种类相等证明来源，也不忽略明确作者属性 |
| task/build/BuildCompanionTask、BuildTaskRecord、BuildOutstanding | 每次真实修改记账、取消保留半成品、最终按现场核对；本体在原挖放核记录，包括部分效果/异常，不在程序结束时补账 |
| gametest/BuildGameTests 的改图/二次无动作/记录保存/中止，以及BuildTaskRecordTest | 学习需要覆盖的边界，自行编写离线回归；未运行参考测试或游戏 |

参考没有与本体需求完全相同的命名设计修订库。这里根据上述数据/实例职责补显式修订，
不是照历史说明猜接口。实例持久化不等于目标生命周期恢复，后者仍属L2。

## 数据入口

新增build_record，当前28项工具（19服务端、9本地）。常驻短说明与tool_help同步；
run_program沿原Schema、原子调用、权限、取消和真终态入口调用。

- design_create：design_id使用1-48位小写字母、数字、下划线或连字符，首位字母/数字；
  definition为cells或fill之一，沿B1坐标、状态和载荷限制，原点与朝向为零。
- design_patch：design_id、design_revision和1-16项edits。每项为完整cell，或{x,y,z,remove=true}；
  重复坐标拒绝，删除不存在的格/删除到空设计拒绝。实际数据未变不增加修订。
- design_query：显式design_revision，offset每16格分页，可用layer筛指定相对y；
  返回概要、所有层号及当前页。design_list每16项列设计。
- instance_create：design_id、design_revision、anchor、rotation可选；保存独立快照。
  实例ID为UUID，绑定当前存档、维度、主人和同伴持久UUID；不同实例目标不得重叠。
- instance_query：instance_id、instance_revision和offset；返回target引用、修订、
  落点/朝向、真实动作数与逐格来源状态。instance_list只列当前主人/身体/维度实例。
- instance_revise：同instance_id/instance_revision与明确design_revision，在未登记工地的
  显式新任务中应用同设计另一修订。落点/朝向不变，不无声更新，不修改已冻结工地或清账。

例如从instance_create/query取得`target={instance_id=...,instance_revision=...}`后，
直接交build_diff、build_site begin、build_nearby或mc.build。服务端解析为同一B1目标，
无需每轮传整图；build_nearby使用引用前必须已登记该实例工地。
原expected_revision仍是完整目标内容哈希，区别于实例/设计的数据修订号。
设计最多1024修订，实例最多1024修订；历史设计不无限保留，旧实例仍保存自己的快照。

## 实际来源与修建

原BlockPlacement在实际回调后读取前后状态和消费，记录变化；只有原空气、消费恰一件、
实际非空气的格才建立可用来源。已有满足格、查询或受理不会认领。
原BlockMining在实际破坏的finally中记录前后变化，原版抛错后已有变化也保留。
动作事件含单调序号、操作、位置、实例修订、前后确切状态和消费；不包含可执行脚本。

实例改图时，自建来源中不再需要的格加入同一目标的显式air要求，总目标仍最多128格。
实际拆除必须具备本实例工地/修订、活见证/原区块/确切状态，且通过B3依赖/通道/
身体支撑、实际材料/工具、原生采收、原许可和控制。有来源的作者状态变化可走同一清障；
外部预置的障碍不会被实例修建顺手认领。修建仍由Lua有限选择，不自动开始或回放。
有承重、工位或通道依赖的旧格保留并报告受阻；不许为了改图拆承重或另开逃生路线。

原地形钩子使同格拆换立即失效，相同方块/状态放回也不能恢复旧来源。
邻格变化不误使本格见证失效，但依赖仍新鲜检查；缺钩子/容量不足/区块重载不授予拆除权。
记录来源跨任务可复用，原路径搜索、缓存重验与活体挖放都保护其格及直接地板。
移除后的来源槽保留为无效墓碑，不通过拆放或改图回收额度。

## 保存、失败与边界

记录位于当前世界的mcbot/buildings.json，使用结构化JSON与同目录临时文件原子替换；
逐次真实修改后同步写入，不等收工/退出。每世界32设计、32实例，每实例128来源格、
256真实变化事件；文件2MiB、嵌套24层。查询不写盘，无淘汰换额。
采用现有名册的世界根目录约定，不使用玩家配置目录，不新增需要猜测映射的SavedData接口。
在规模上限内仍可能有主线程文件写入停顿；没有实测速度承诺，性能另按P1现场证据处理。

重进可读设计、独立实例快照和部分施工历史，重新查询真实差异；没有自动目标恢复、
动作重播、恢复许可或补充预算。实时见证不序列化：跨退出/卸载后即使同状态仍在，
无法证明期间未被替换，故呈conflict；实际空气可在明确新调用和原门内修补。
原记录不会仅凭重新查询或状态相等重新取得拆除权。这里不宣称持久所有权认证已实现。

原子替换保证单份记录不被半写截断，不承诺跨Minecraft世界文件与记录文件的崩溃事务；
崩溃重进后保守失去拆除权，按现场重查。记录损坏/过大/符号链接/读写失败不覆盖原件，
标记不可用并阻止建筑与地形修改；实际已经发生的部分效果保留。
动作回执recording_known报告记录可用性；超限回执仍保留此标记，下一动作不继续。
临时工程仍沿B3任务内来源；取消不会自动拆除或把临时块升级为永久实例来源。
