# 施工层窗口与路线连续性（2026-10-26）

## 参考机制

参考项目的施工任务先把可施工目标按最低 `y` 层建立窗口，再按层内阶段处理：

- 低层优先，未完成的基础层不会因为分页或远端候选而自动升到上层。
- 同一层内先完成当前阶段，再从这一层尚未处理的目标中选择距离身体最近的格。
- 一遍施工持续使用当前层窗口，只有这一层的候选全部轮过或现场事实变化后才重排。
- 目标状态、材料和身体位置在动作前重新核对；失败的单格不会把整层或整栋标成永久不可动。

这套机制的价值是让路径跟着当前工作面收敛，减少在两个远端区域间交替寻路，也减少为了换路线而拆掉仍有用的临时支撑。

## 本体落地

`BuildWork` 的自动近身批次现在在有限候选内保持最低层，并在同层选择距离身体最近的 `ready` 格；没有可用身体对象时回退到原有确定性图纸顺序。`workLayer` 会贯穿本批次，批次结束后由下一次新鲜差异重新确定层窗口。

Lua `mc.build` 继续负责跨页、清障、远端到位和待补修复。施工仍有 `ready`、`needs_clear`、可用远端候选或待补格时，不因临时工程账达到 16 条就调用清理。临时工程只在无候选停滞、最终收尾或显式清理时回收，避免：

```text
编辑路线 -> 提前回收支撑 -> 下一路线重新搭支撑
```

完成或清理重新打开原图目标时，仍会按同一修订继续做新鲜差异核对；来源、设施、依赖、权限和原版动作守卫不变。

## 边界

参考项目没有与本插件完全等价的自动脚手架回收账，因此本轮只迁移已验证的施工顺序和局部工作面思想，没有用更宽的“硬保护”替代现场事实，也没有复制参考代码或资源。复杂封闭现场仍以日志中的实际导航、材料和原版放置回执为准。
