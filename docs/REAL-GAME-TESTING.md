# mcbot 首轮实机必测与反馈

请在新建测试世界里依次完成下面 18 项本体测试，每项做完记录结果。我们重点检查真实动作、物品数量、权限和停止任务，首轮不做复杂地形、满背包、特殊配方、附魔或模组兼容测试。连接器装好后再做 B01。

手册日期：2026-10-11。源码基线：main `60e523f75555bc00eebb6233a687b43df0ec8bfd`，PR #7–#11 已合并，#5 未合并。

测试包：`mcbot-0.1.0.jar`，SHA256 `9d1260f975bc7f4005f63561c598fa5cd9f52c562fe869d2bbf0f8d916935b38`。请维护者提供此包；旧包也叫 0.1.0，不能只凭名字判断。联机服和客户端须一起更新。

合并后离线测试 563 项通过，以下实机项目初始全部“未测”。建议分两次：T01–T10、T11–T18；合计约 90–150 分钟，配置或模型慢时会更久。

## 先准备一次

1. 关闭游戏，把新包和 Fabric API 放入该实例的 `mods`，移走旧 mcbot。要求 Minecraft 1.21.11、Fabric Loader 0.19.5、Fabric API 0.141.6+1.21.11、Java 21。首轮不加其他玩法模组或数据包，不会配置请维护者帮忙。
2. 新建“mcbot测试A”，创造、超平坦、允许作弊。不要用重要存档。测试者用创造准备物品，同伴需要自己的材料和工具。
3. 按 T 打开聊天。`/` 开头是游戏命令；`@bot` 是给同伴的任务，不加 `/`。也可在 G → 任务中输入，此时不加 `@bot`。
4. 一次只发一项任务，等实际结束后再发下一项。“已受理”只是开始。出错先核对现场，不反复重发。
5. 要停止时 G → 任务 → 停止任务。停止不回滚已搬物品/已放方块，也不会熄炉。出现复制/丢物、未确认就开路、停止后续跑，立即停相关测试并留日志。

完成 T01 后，在没有活动任务时每行单独执行，建立固定场地：

```text
/fill 96 79 96 118 79 108 minecraft:stone
/fill 96 80 96 118 85 108 minecraft:air
/tp TestBot 100.5 80 100.5
/tp @s 98.5 80 100.5
/setblock 102 80 100 minecraft:chest
/setblock 102 80 103 minecraft:crafting_table
/setblock 102 80 106 minecraft:furnace
/setblock 104 80 106 minecraft:blast_furnace
/setblock 106 80 104 minecraft:smoker
```

这些命令会清掉指定区域，只在测试A使用。命令出错保留红字原文，请维护者帮忙，不猜命令。坐标都是绝对坐标。每项注明“归位中心”时，无任务状态输入 `/tp TestBot 100.5 80 100.5`；注明“靠近炉子”时输入 `/tp TestBot 103.5 80 103.5`。

测试箱 `(102,80,100)` 初始放：橡木原木 8、圆石 16、煤炭 8、粗铁 6、生牛肉 3、铁镐 1、钻石镐 1、铁斧 1。准确拆分数量，不额外放木板/木棍。每项缺材料时从这个箱子补给，补给前后单独记账。

## 怎么记结果

直接打开 `dist/game-testing.html` 填写，结束点“导出反馈 JSON”，把文件和日志交回。也可填 `docs/templates/GAME-TEST-FEEDBACK.md`。反馈只保存在本机，自动保存只是辅助，每次结束都导出。

结果选 **未测 / 通过 / 失败 / 阻塞**。同时填“指定工具是否执行”：执行了 / 没执行 / 看不清。不知道就写“看不清”，附面板记录。模型没调用要求的工具，填阻塞；仅口头说完成不能算通过。多个子检查各写结果，不用一个“通过”覆盖没做的部分。

填写时间和时区（如 `2026-10-11 20:15 +08:00`）、实际现象和数量、附件名。失败另给问题编号“问题01”，以后复测保留旧记录并追加新版本结果。不会准备就填阻塞，维护者再补。

## 第一轮 基础动作和三类炉子

### T01 进游戏召唤和模型读取

1. 进入测试A，按 G → 同伴，填 `TestBot` 点召唤；先点任务页“查看状态”和“扫描附近”。这两按钮不需要模型密钥。
2. G → 模型，填写维护者私下提供的地址、完整模型名和密钥，点“测试连接”，成功后“保存并应用”。模型调用可能收费，失败不要反复点。
3. 连续发下面指令两次，每次等结束再发：

```text
@bot 只读取自己的完整背包和状态，再扫描附近并简短汇报。
```

预期：一个同伴，按钮和两次模型任务都有真实状态，位置/主手与现场相符，不空回复或报工具配对错误。连接测试通过不能代替两次游戏任务通过。

记录：实际环境版本、模型名（不填密钥）、两次时间、回执。随后建立上面的场地。

### T02 背包切换和箱子往返守恒

准备：归位中心，测试箱按初始清单装好。

```text
@bot 用transfer取出箱子(102,80,100)的全部物品，再用inventory列出各槽数量、主手和工具耐久。先不做其他操作。
```

再让同伴按读到的铁镐槽号用 equip 切到主手；随后用 transfer 把全部圆石存入同一箱子，再全部取回。

最后在同伴脚边丢泥土5个，你退到8格外，等约2秒后让同伴只用 collect 捡自己脚边半径3的物品，不移动。

预期：初始数量一致、箱子取空；切手保留整个堆栈和耐久；圆石存入时同伴0/箱子16，取回时同伴16/箱子0；拾取后同伴泥土增加5、地面减少5。transfer 目前搬所有匹配物品，没有指定搬几件的参数。

记录：背包/箱子/地面数量，切手前后槽号和耐久。普通背包槽9–35与主手槽交换，快捷栏0–8只是选中；你误捡的物品也要算入总数。

### T03 材料搜索和箱子明细

准备：归位中心，放橡木原木 `(100,80,103)`；箱子放钻石2，在箱子右下角第27格放金锭3。

```text
@bot 只用find_resource查找#minecraft:logs，半径8，报告坐标；再用inspect_block读取箱子(102,80,100)，有next_offset就读下一页。只读，不取物品。
```

预期：能找到指定原木，箱子两种物品/数量和末页正确，世界和物品不改变。普通扫描没有木材分类，不能替代 find_resource。

记录：资源坐标、两页结果及现场。结束后由你清空箱子，留下原木不影响测试。

### T04 平地移动到真实终点

准备：归位中心，至 `(108,80,100)` 路上为空、地板完整。

```text
@bot 只用move_to走到(108,80,100)，不能挖放；等真正结束再报告位置。
```

预期：同伴实际逐步走过去，终点接近目标，平路不要求改地形许可，不刚受理就说到了。

记录：起终点、录像或截图和用时；结束后归位。

### T05 正确采收和错误工具拒绝

准备：放石头 `(101,80,100)`，铁镐主手，记圆石数/耐久；你退开避免捡走掉落。

```text
@bot 只用break_block挖(101,80,100)这一格石头，等完成再查看背包和铁镐耐久，不挖其他格。
```

随后补回石头，把主手换为原木，再要求同一 break_block，不换工具，拒绝就停。

预期：第一趟有挖掘过程，石头消失、圆石总数增加1、镐有实际损耗；第二趟工具不合适（如 WRONG_TOOL），石头和物品保持。掉落在地面也计入总数。经验不保证自动收取。

记录：两趟主手、前后数量/耐久、拒绝回执。模型自行换回镐时第二趟填阻塞。结束后你移走石头。

### T06 准确放置和占位拒绝

准备：归位中心，`(101,80,101)` 为空，下方为石头。

```text
@bot 只用place_block在(101,80,101)放1个圆石，再查背包；不放其他位置。
```

原格保留，再让同伴只尝试往原格放一次，失败就停，不换邻格。

预期：第一次准确放置、消耗1件；第二次占位拒绝，不多消费，也不转去旁边。

记录：两趟数量、目标及邻格截图。测完由你清掉圆石。

### T07 合成查询成功和缺料

准备：归位中心，工作台保留，有原木、圆石；初始没有木板/木棍。

1. 要求 craft `minecraft:oak_planks` count4、query=true；核对查询没消费。
2. 发送：

```text
@bot 用craft制作minecraft:oak_planks至少8个，再制作minecraft:stick至少5根，再制作minecraft:stone_pickaxe至少1把，最后查看背包。不制作其他物品。
```

3. 把剩余木棍全部存进测试箱，再要求 craft 石镐1把；缺料就停，不补料。

预期：查询不改背包；成功流程原木少2、木板最终增加4、木棍最终增加6、圆石少3、石镐增加1。请求5根木棍按两次配方实际产8根，其中2根用于镐。缺料失败不先消费圆石。

记录：查询、成功、缺料各自数量和回执。结束取回木棍，清空箱子。

### T08 熔炉实际烧制

准备：靠近炉子，熔炉 `(102,80,106)` 三槽清空，有粗铁3/煤炭1。

```text
@bot 先用inventory核对来源槽，用smelt向熔炉(102,80,106)装粗铁3个和煤炭1个，等待40秒，再查询，取产物最多3个，最后查看背包。
```

预期：界面真实有火/进度，粗铁减少3、铁锭增加3，煤炭按原版消耗。装料/等待不等于已出货，卡顿时记录实际产物和炉内余量，不重复装料。

记录：三槽截图、前后数量和回执。先保证本项过，再做其他机器。

### T09 高炉实际烧制

准备：仍靠近炉子，高炉 `(104,80,106)` 清空，有粗铁3/煤炭1。

```text
@bot 核对来源槽，用smelt向高炉(104,80,106)装粗铁3个和煤炭1个，等待25秒，再查询取产物最多3个，最后查看背包。
```

预期：高炉实际工作，铁锭再增加3、原料/燃料正确。三类机器配方和实际运行不同，不能只测熔炉就略过本项。

记录：本次数量增减、三槽和回执。

### T10 烟熏炉实际烧制

准备：仍靠近炉子，烟熏炉 `(106,80,104)` 清空，有生牛肉3/煤炭1。

```text
@bot 核对来源槽，用smelt向烟熏炉(106,80,104)装生牛肉3个和煤炭1个，等待25秒，再查询取产物最多3个，最后查看背包。
```

预期：生牛肉减少3、牛排增加3、实际出货。

记录：前后数量、三槽和回执。本轮不单独重复测全部燃料/取出组合，出错时再由维护者定位。

## 第二轮 权限停止流程和保存

### T11 明确只读不能产生动作

准备：归位中心，目标格为空，拍位置/背包/目标截图。

```text
@bot [只读] 查状态后，尝试向(108,80,100)移动并在(101,80,101)放圆石。任务必须遵守只读限制。
```

预期：查询可用，移动/放置不能发生。如果模型自行遵守而没尝试动作，记录“动作工具没执行”，不能声称服务端拒绝链已实测。

记录：实际调用、拒绝/解释与前后现场；出现动作立即停止并报问题。

### T12 执行中停止后新任务可用

准备：归位中心，钻石镐主手，放黑曜石 `(101,80,100)`。

```text
@bot 只挖(101,80,100)的黑曜石，完成后扫描附近。
```

看到裂纹后立即 G → 停止任务，观察10秒，然后发 `@bot 只查看自己的状态。`

预期：没挖完时取消应清裂纹、停止后续破坏及扫描，新任务正常；旧回执不让旧任务恢复。停止前已经挖完则取消场景填阻塞。单人暂停游戏不能替代取消。

记录：取消时间、短视频、方块/耐久变化、新任务回执。结束你清场。这里测真实身体停手，T15另测组合流程不继续下一步，二者不能互相替代。

### T13 改路先拒绝再确认

准备：没有任务时执行以下命令，建立只可挖穿的封闭通道；铁镐主手。这样排除同伴合法绕路导致的无效测试。

第一次看到清单后答 `@bot 答 不同意`，核对墙没动；重新发任务，看到新清单后答 `@bot 答 确认`。

预期：拒绝不挖；批准本次具体清单后才挖穿、到达，不沿用旧问题。肯定答案只写“确认”两字，长解释句可能不授予权限。

记录：两次清单、拒绝/批准和实际改动/终点。结束归位；首轮不做复杂重规划专项。

### T14 真实攻击和保护边界

准备：请维护者帮你搭有顶、无日光的小场地；难度普通，只有一只未命名僵尸，同伴铁斧主手、近身，你和其他生物退开。

```text
@bot 扫描并选择准备好的这一只近身僵尸，用attack最多出手2次；不追击、不换目标、不拾取掉落，按实际生命和出手汇报。
```

再做两项安全检查：用扫描的真实编号/UUID尝试攻击玩家，拒绝就停；另准备一只牛，尝试攻击最多1次，出现具体确认后回答 `@bot 答 不同意`。

预期：僵尸真实受伤、有冷却间隔，最多2次；没死不能说击杀，超距可提前停止。玩家拒绝，牛未批准不出手。模型没调用相应工具时记阻塞，不能用创造玩家不掉血代替拒绝证据。同伴目前无敌，不测其死亡。

记录：三种目标各自的实际工具/回执/挥击，录像优先；编号不能凭空猜。

### T15 组合流程成功失败和取消

准备：归位中心，有至少2个橡木原木、圆石、背包空间，`(101,80,101)` 为空。

下面三段较长，请在 **G → 任务** 输入框粘贴，每段删掉开头的 `@bot ` 再点“发送”。不要粘贴进普通聊天，以免长度限制截断JSON；一段只发送一次。

成功清单：

```text
@bot 只调用一次workflow执行清单，不拆成逐项模型调用。参数：{"steps":[{"tool":"craft","args":{"item":"minecraft:oak_planks","count":8}},{"tool":"craft","args":{"item":"minecraft:stick","count":5}},{"tool":"inventory","args":{}}],"timeout_seconds":90}
```

失败清单：先把全部木棍存箱，再执行下列任务；测完取回木棍。

```text
@bot 只用workflow执行原清单，不补料不重试。参数：{"steps":[{"tool":"craft","args":{"item":"minecraft:stone_pickaxe","count":1,"query":true}},{"tool":"place_block","args":{"x":101,"y":80,"z":101,"item":"minecraft:cobblestone"}}],"timeout_seconds":60}
```

取消清单：目标仍为空，执行后看到圆石放好、开始等待就停止，观察35秒。

```text
@bot 只用workflow执行清单。参数：{"steps":[{"tool":"place_block","args":{"x":101,"y":80,"z":101,"item":"minecraft:cobblestone"}},{"tool":"wait","args":{"seconds":30}},{"tool":"craft","args":{"item":"minecraft:stick","count":1}}],"timeout_seconds":90}
```

预期：成功实际原木少2、木板增加4、木棍增加8；缺条件停在第一步、圆石不放；取消保留已放圆石和1件消费，后续木棍合成不执行，汇报保留已完成步骤。三者各记结果。

记录：workflow是否真的调用、各步回执、数量、取消时间。模型改清单或不用workflow记阻塞。首轮不重复测13步等已被离线覆盖的参数枚举。

### T16 反问一次回答和配置重载

```text
@bot 用ask_owner问我“下一步查看背包还是扫描附近”，等回答后只执行选择的一项。
```

出现问题答 `@bot 答 查看背包`；结束后重复同一答案，应拒绝且不新建任务。

再提一次同样的问题，这次不回答；G → 模型，保持配置不变点“保存并应用”，随后答 `@bot 答 查看背包`，最后提交新的只读状态任务。

预期：第一次答案续跑一次；重复答案无效；配置保存结束旧任务/问题，旧答案不能续跑，新任务正常。首轮不专门等两分钟重复测所有过期组合。

记录：问答/保存时间、重复/旧回答拒绝、新任务结果。不要同时换模型。

### T17 完全关游戏后恢复完整状态

准备：让同伴到一个不同于出生点的安全位置，记录完整非空槽/数量/耐久/选中主手、身份和位置；不要只拍手里的镐。记三台机器剩余槽，如都空也写空。

1. 正常退出世界，关闭整个游戏，再从启动器重开。
2. 重进测试A，不重复召唤，读状态/完整背包，开机器核对。

预期：同一同伴和完整物品状态恢复，位置正确，机器内容保留，没有旧任务续跑；配置仍能用。首轮用整客户端重启覆盖持久化，不再单独做一遍仅退出标题的重复对照。

记录：关/开时间，完整前后对照，关闭前日志副本。

### T18 同一客户端两个世界不串用

准备：测试A已有非空背包样本，记状态；正常退出世界，保持整个客户端不关闭，新建测试B。

1. 首次进B不召唤，检查没有A的同伴。
2. B召唤 `TestBotB`，给泥土2并记状态；退出B回A，再回B核对。

预期：A/B各自的同伴、背包、位置正确，不串旧问题/任务。API配置是客户端级、可以相同，这不属于世界串用。

## 连接器准备好后必测

### B01 宿主到游戏的任务问答和取消

准备：连接器由协作者安装、配置，使用同一游戏实例的本地桥；不要求新手改N.E.K.O源码或拼HTTP请求。未安装填阻塞，本体T01–T18照常测。
