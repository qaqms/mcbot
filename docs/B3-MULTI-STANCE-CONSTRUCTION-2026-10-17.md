# B3：多站位施工与临时工程

本卡沿原动作/事实入口实现任务内施工组合，承接B1/B2/N3/F2。
模型先选择目标、范围、通道和必要临时工程；Lua只在有限工作集合里排序、调用和重查。
不生成房型，不自动采集/合成/补给，不增加依赖求解器，不扩大模型步帽或重开原探索/许可。
最新验证、候选及提交以STATUS/Git为准；本文不把离线替身写成原生游戏验收。

## 共用入口

新增服务端build_site，当前27项工具（18服务端、9本地）：

- `operation=query`仅观察；不带其他字段。
- `operation=begin`提供同一B1 target、2-64个世界脚格access_route，可选bounds。
  通道须水平四邻接、无重复、含当前脚格、空气净空和稳定整格地板，至少一个端点在全目标
  水平包围范围外。非空气目标不能占通道的脚格或头部格。只支持宽不超1、高不超2的身体。
- bounds默认首次脚格64格球；显式范围与目标、通道、身体必须相容，任务内冻结。
  同目标/通道/范围再次begin只核现场，不清账；更换目标、通道或范围拒绝，实例修订另属B4。
- `operation=checkpoint`带expected_revision。实际目标与六邻接状态、材料可用性、采收资格、
  站位及临时工程状态组成有限轮次证据。补料、换合格工具、真实支撑变化可用原剩余预算重评；
  回到以前的条件、同缺口往返、仅查询/时钟/扣料均不能补次数。

build_diff仍只读，不会因查询就登记工地。新增cells.item/material_available/clear_allowed和
observation_key；key含整目标实际状态、相关真实材料及区块版本，用于Lua跨页一致性检查，
不是持久实例修订。完整目标修订仍由B1规范数据生成。

run_program提供内置Lua函数，正文位于agent-core资源construction.lua：

```lua
local target = {
  anchor={x=4,y=90,z=0},
  cells={{x=0,y=0,z=0,block="stone"}}
}
return mc.build(target, {
  access_route={{x=0,y=90,z=0},{x=1,y=90,z=0}},
  bounds={x=0,y=90,z=0,radius=16},
  max_rounds=4,
  max_actions=2
})
```

示例坐标只是输入形状，调用者必须先查真实通道/目标，不直接照用。
助手查同修订全部明细页，稳定且完整才选本轮：当前可做页→可安全清障目标→有材料的远处目标。
使用原build_nearby、只行走move_to工作到达、单格break_block，再重查差异。
每次接受回执仍等真正终态；局部移动失败只经原mc.try_call门读取，继续修改前先完整新鲜status。
新增桥返回failure_kind供助手区分TARGET_LOST并立即停止；不增加可吞失败类别。
权限、安全、缺料/工具、未知、硬预算、取消均不自动重试或另开路线。

助手正常结束也可能返回`goal_satisfied=false, blocked=...`，表示有限程序正确收场但目标未满足。
只有最后同修订新鲜完整全目标差异可返回true；batch终态不能代替这一步。
`outer_goal_verified=false`明确外层set_goal建筑验收仍属L1，不能凭Lua返回直接完结任意自然语言目标。

## 保护与原预算

完整目标沿用B1的128格上限，工地自己的保护索引不占用/扩大旧WorkTargets的64格集合。
规划、缓存清单重验、活体执行和单格挖放共用保护：目标、非空气目标直接地板、
非整块目标的邻接依托、原工位及支撑、声明通道和实际走过的格子/地板。
NavigationTrail沿原任务最多256条实际接地记录积累保护；有观察缺口或记录截断就停工。
路线不能穿过尚未建成的非空气目标脚/头格，以免走进去后再把退路砌上。
登记通道不是任意世界返程证明，`return_guaranteed=false`；外力破坏仍须新鲜导航，
不自动拆成品另开逃生路，也不保证任意分数地板/洞穴/动态实体情况下可返。

施工清障必须显式携site_revision与expected_block，不和clear_obstructions组合。
只允许冻结目标中的非成品障碍，须有替换材料、没有承重/贴附/工位/通道/身体依赖；
同种不同作者状态交回模型，不自动反复拆放。真正破坏仍走BlockMining原采收、安全、视线、
耐久、掉落来源与终态；不把掉落消失当入包。单放/路径垫块/施工继续共用BlockPlacement。

工地累计16个checkpoint、128次原生挖放尝试、16条临时来源；不淘汰旧项换额度。
工地move_to共用同一个原NavigationBudget：8000节点、32768记录、400ms协作CPU、2次重算，
跨换位/程序/失败/暂停保留。原PathSpec与工地范围取交集，D2避险也不能借工地越界或拆成品。
原路径3600刻、近身施工200刻/12动作/400ms、每页50ms/96预检继续生效。
Lua默认16轮/每批4动作，可在现有上限内调低/调高；程序默认300秒、最多900秒，
max_calls默认128/最多256、原指令/内存/输出限制不变，库函数也计原账。
build_nearby仍按max_actions在客户端预扣原子预算，其余每个工具调用照常扣账；
没有失败退款、换阶段补额或暂停续时。身体抢占恢复继续由原scheduler/BodyControl执行。

## 临时工程

Lua可在options.temporary中明确最多16个`{x,y,z,item,face?,purpose}`，不是自动生成支撑树。
也可直接使用place_block的temporary_purpose或同名move_to放置工作参数。
用途只支持support或workstation；后者须无方块实体工位。原格须空气，不能覆盖目标、
通道、已走过的格子或已有临时记录，只支持原投影允许的无组件稳定单格整块。
允许在缺失的目标依托处放临时支撑；当它仍支撑目标时不能回收。
工地内普通路线实际垫块也在同一放置核心记为support，不能只有NavigationTrail坐标却无来源。
目标已满足时不会先搭临时工程；已有有效临时记录复用，未知/已换同种方块不认领或自动补放。

只有实际放置后观察到一件消费、原空气与实际非空气状态，才登记位置、用途、确切状态、
原区块对象及CellWitness；预检、受理或预测都不记实际来源。
TerrainVersionMixin沿已有原生setBlockState回调使该格见证失效，拆掉再放回相同状态也不能恢复。
邻格普通修改不会误使本格失效；区块卸载/全局失效或实例替换会拒绝旧来源。
每区块最多64个仍被引用的见证，弱引用过期可回收，容量不足/无原生钩子返回未知，不能回收。

回收须另行显式`mc.cleanup_temporary(revision)`或break_block的temporary_cleanup=true。
仍走原工作导航、最新build_site事实、采收/原许可/原范围及真实挖掘，逐刻复核：

- 来源见证、区块身份、确切状态仍有效；原记录不是给替换物的拆除许可。
- 目标、通道、实际经过格、身体/活物脚下、上方承重或相邻贴附/工位/未知条件没有依赖。
- 六邻接仅对干燥稳定整块侧面/下方采用狭窄允许条件；上方仍有方块就保留，
  不承诺任意模组结构工程。实体占位报告或停工，不攻击/搬移玩家。
- 拆掉后记录槽仍消耗，present/present_known与来源有效性分开，空气不报成“仍保留的材料”。

助手不会默认收尾回收，更不会在取消、断连、退出时拆临时块。
本卡事实仅在原身体/任务/世界内有效；新任务不能继承拆除权，跨任务保留设计/来源、
外部冲突、保存重进由B4继续完成，不把此处内存账冒充持久建筑实例。
服务端任务对象的身份也参与隔离，重连后相同数字task_id不能继承旧工地。
本卡不会为回收而证明另一条替代退路：本任务已走过的临时地板始终保留，
即使肉眼看起来已有别的路，也不自动解除这份依赖。
