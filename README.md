# mcbot

一个 LLM 驱动的 Minecraft 同伴 **agent 框架**：玩家用自然语言提交任务，模型自主拆解、
规划并逐步执行移动、挖掘、拾取、放置、存取、主手工具切换、普通配方合成、熔炉类机器操作及有界近战，
依据工具反馈调整策略。熔炉操作及 C1–C4 的实现/离线验证完成，真实机器与动作仍待验。
当前按物品守恒 → 挖放语义 → 调度与权限 → 攻击 → 状态感知与流程组合的顺序完善本体。

## 拓扑（三进程）

```
N.E.K.O 宿主及适配连接器 ⇄ 127.0.0.1 任务桥(HTTP/SSE/MCP) ⇄ mcbot 大脑+工具宿主(所属玩家客户端) ⇄ Minecraft 网络 ⇄ 联机服务器(假玩家身体 + 服务端工具执行 + 三道闸)
```

- **大脑在客户端**：agent loop 与 LLM 调用运行在所属玩家的客户端，使用其本地配置的 API key；
  key 永不经过服务器。
- **身体在服务端**：同伴是服务端的假玩家（`ServerPlayer`），动作由服务端工具执行并逐一校验。
- **桥接是任务级**：连接器通过任务、事件、问答与取消接口接入，不直接调用原子游戏工具。

## 协作与接入

mcbot 提供 MC agent 本体与任务桥；N.E.K.O 等宿主的适配连接器负责宿主侧任务接入与反馈展示。
模块间以 [`docs/BRIDGE.md`](docs/BRIDGE.md) 的 v1.0 契约协作，Schema、示例及验收流程见该文档；
快速上手见 [`dist/README-BRIDGE.md`](dist/README-BRIDGE.md)。
内部实现可以独立迭代，破坏性接口变更需发布新版本并协调接入迁移。
接口自动化通过不等同端到端联合验收完成，当前进度与待验项见 [`STATUS.md`](STATUS.md)。

## 结构

- `agent-core/` — 纯 JVM 大脑层（LLM 客户端、对话压缩、agent loop、护栏、桥接内核），**零 Minecraft 依赖**，可独立测试。
- `src/main/` — 服务端 + 公共层：假玩家身体、任务调度、服务端工具与三道闸、命令。
- `src/client/` — 客户端层：agent 宿主、S2C 通道、G 面板、桥接 HTTP 服务。

## 构建

需要 JDK 21。`./gradlew build` 产出 mod jar；`./gradlew runServer` 起本地开发服做无头自测。
工具链版本钉在 `gradle.properties`（Fabric 1.21.11 + loom-remap）。
